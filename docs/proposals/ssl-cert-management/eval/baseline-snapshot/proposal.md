# Proposal: SSL 证书统一托管与更换平台（e-cam 证书管理功能域）

## Problem

多云环境（阿里云/腾讯云/华为云/AWS/Azure）下的 SSL 证书更换目前是纯手工操作：每张证书到期需要在多云的 DCDN/CDN、WAF、ALB/CLB/NLB、多云 K8s 自建网关（ALBConfig 等 CRD）、约 150 台 VM Nginx 上逐处更换，没有统一台账，无法清晰看到各子域名证书的到期时间，也无法回答"这张证书被哪些资源引用"。换证频繁（付费证书周期短）且极易漏换，漏换即线上 HTTPS 事故。

### Evidence

- 证书来源为外部付费平台购买的 EV/OV 证书，无法通过 ACME 自动签发，签发环节只能人工完成
- 引用点多且分散：多云 DCDN/CDN、多云 WAF、多云 ALB/LB、多云 K8s 集群自建网关（通过 ALBConfig 等 CRD 引用云上托管证书 ID）、约 150 台多云 VM 上的 Nginx
- 现状操作路径示例（K8s 网关）：进入集群 → 工作负载 → 自定义资源 → 编辑 ALBConfig → 手工把旧证书 ID 换成新证书 ID——每次换证全网重复此类操作十几处
- 无统一台账：无法按子域名查看证书到期时间、无到期预警、无证书文件完整性检查、无引用关系视图

### Urgency

每轮换证都是一次全网高危人工变更，成本高、周期长、易漏；随着引用点数量增长，漏换导致生产事故的风险持续累积。当前无任何系统化支撑，每延迟一轮证书周期就多承受一轮全网手工变更风险。

## Proposed Solution

在 e-cam 平台（后端 e-cam-service / 前端 e-cam-web）新增**证书管理功能域**，围绕"人工购买 → 平台托管 → 自动发现引用 → 一键批量更换 → 验证生效"闭环：

1. **证书托管台账**：导入证书文件（证书 + 私钥），私钥加密存储；列表/详情/删除；解析证书的域名（SAN）、签发机构、有效期等要素
2. **完整性检查**：导入及巡检时校验证书/私钥匹配、证书链完整性、SAN 域名覆盖、有效期；与线上实际生效证书比对
3. **引用关系发现**：基于已有云账号与资产同步能力，只读扫描多云 CDN/DCDN/WAF/LB 的证书引用；扫描多云 K8s 集群的网关 CRD 中的证书引用；与平台托管证书按域名/指纹关联，形成"证书 → 资源"反向视图
4. **到期监控与告警**：按子域名的到期时间看板 + 分级告警（30/14/7 天）+ TLS 主动探测（对各子域名端点握手读取线上实际生效证书，无需接入服务器即可覆盖 Nginx 场景的到期监控）
5. **一键批量更换**：导入新证书后自动匹配同域名旧证书的全部引用点，展示变更清单 → 人工确认 → 批量执行（首期覆盖阿里云、腾讯云全套 CDN/DCDN/WAF/LB 部署器 + 多云 K8s CRD 证书引用更新）→ 逐项进度 → 失败可回滚（恢复旧证书引用）→ 变更报告
6. **可插拔执行���道**：变更执行与目标资源之间通过通道抽象解耦——云 API 通道、K8s API 通道首期实现；堡垒机通道（VM Nginx）、优维 Agent 通道预留接口二期实现

### Innovation Highlights

- **引用关系自动发现**是本方案区别于行业方案的核心能力：Certimate/Certd 等开源工具只能管理"自己部署过的"证书，无法发现存量资源已经引用的证书；本方案基于 e-cam 已有的多云账号凭证与资产同步框架，可对存量全网引用做只读发现并建立反向视图
- **可插拔执行通道**适配企业网络现实：平台不能直连 Nginx 服务器，执行通道抽象使"堡垒机 → 优维 Agent"的演进不改变上层更换逻辑
- **TLS 主动探测**用零侵入方式覆盖 Nginx 到期监控：���装 Agent、不走堡垒机，握手即可读取线上生效证书并与台账比对
- 其余为证书管理领域的标准做法（台账、加密存储、完整性校验、批量变更），属于常规采用，不另作创新声明

## Requirements Analysis

### Key Scenarios

**Happy path**
- 运维导入新购证书（PEM + 私钥）→ 系统校验通过、解析要素、加密入库
- 运维查看某域名证书 → 看到全部引用资源（多云 CDN/WAF/LB、K8s 网关 CRD）
- 到期看板按子域名展示剩余有效期；30/14/7 天分级告警推送
- 换证：导入新证书 → 系统列出同域名旧证书全部引用点及计划动作 → 人工确认 → 批量执行 → 逐项成功/失败状态 → 变更报告 → TLS 探测验证线上已生效新证书

**边界场景**
- 导入的证书与私钥不匹配 / 证书链缺失 / SAN 不含预期域名 → 拦截并明确报错
- 同一域名存在多张未过期证书（新旧并存）→ 引用视图按实际引用区分展示
- 证书已导入但引用发现尚未扫描到 → 标记"未发现引用"而非视为无引用
- 探测发现线上生效证书与平台台账不一致 → 差异告警

**错误场景**
- 批量更换中部分资源执行失败 → 失败项保留旧证书引用并可一键回滚，已成功项出具明细
- K8s 集群不可达 / CRD 更新冲突 → 记录失败原因，不阻塞其他目标执行
- 云 API 限流 → 退避重试，超限后标记失败并在报告中体现

### Non-Functional Requirements

- **安全**：私钥加密存储；任何接口与前端不得返回明文私钥；证书变更全部留审计记录；权限接入现有 EIAM 统一权限体系
- **可靠性**：批量变更逐项隔离，单点失败不影响整体；可回滚
- **及时性**：到期告警按天级巡检触发；变更执行进度实时可见
- **可扩展性**：新增云厂商部署器 / 新执行通道不改上层流程

### Constraints & Dependencies

- EV/OV 证书无法自动签发：签发（购买）环节永远在平台外部，平台起点是"导入"
- 平台不能直连 VM Nginx：首期 Nginx 仅 TLS 探测监控，配置级引用发现与更换依赖二期执行通道（堡垒机/优维 Agent）
- 部分云产品仅接受"云上托管证书"：更换需两段式（先上传到该云证书库，再绑定资源），各云证书库 API 能力需逐云验证
- 多云 K8s 集群需平台具备接入凭证与 CRD 读写权限
- 依赖已有能力：云账号凭证管理、资产同步框架、异步任务框架、EIAM 权限（均已存在）

## Alternatives & Industry Benchmarking

### Industry Solutions

- [Certimate](https://github.com/certimate-go/certimate)：开源 ACME 工具，申请/部署/续期/监控全流程，面向自动签发场景
- [Certd](https://github.com/certd/certd)：开源证书申请+部署自动化，阿里云 CDN/DCDN/WAF/SLB 插件生态成熟
- [AllinSSL](https://allinssl.com/)：证书全生命周期管理，多 CA
- 阿里云[证书托管服务](https://help.aliyun.com/zh/ssl-certificate/deploy-ssl-certificates-to-alibaba-cloud-services)：付费托管额度，仅覆盖阿里云产品

| Approach | Source | Pros | Cons | Verdict |
|----------|--------|------|------|---------|
| Do nothing | — | 无成本 | 每轮换证全网高危手工变更，漏换即事故，随引用点增长风险持续上升 | Rejected: 痛点明确且随规模恶化 |
| 纯用开源工具（Certimate/Certd） | 开源社区 | 免费、部署器成熟、开箱即用 | 核心面向 ACME 自动签发，与 EV/OV 人工签发模型不符；无存量引用关系发现；独立账号体系与权限，不融入 EIAM/e-cam | Rejected: 无法覆盖核心场景（引用发现 + 存量更换）|
| 混合：开源工具管续签 + e-cam 只做监控 | 社区 + 自建 | 各取所长 | 两套系统两套凭证，用户跨平台操作；开源工具对 EV/OV 导入更换支持有限 | Rejected: 体验割裂且核心痛点仍在 |
| **自建 e-cam 证书管理功能域** | 本提案 | 复用云账号凭证/资产同步/任务框架/权限体系；存量引用关系发现为独有能力；执行通道抽象适配堡垒机→Agent 演进 | 部署器需自研，工作量大，需分期 | **Selected: 唯一能同时满足"引用发现 + EV/OV 托管更换 + 权限一体化"的路线** |

## Feasibility Assessment

### Technical Feasibility

- 后端全部依赖已就绪：云账号 AK/SK 管理、多云 SDK 适配层（已有 6 云接入）、CDN/LB/WAF 同步器已采集证书名字段、异步任务框架、EIAM 权限
- 证书解析/校验、TLS 探测为成熟技术领域，无技术阻塞
- 风险点在各云证书绑定 API 的差异与限制，需逐云做 API 能力验证（PoC 性质任务列入任务分解）

### Resource & Timeline

首期范围（双云部署器 + 全量监控）为可控的分期切分；阿里云、腾讯云证书 API 文档完善。具体估算在 tech-design 阶段给出。

### Dependency Readiness

- 云账号凭证：已有 ✅
- 多云 K8s 集群接入凭证：**待准备**（需采集各集群的访问凭证并授权 CRD 读写）
- 告警渠道���webhook + 邮件）：通道待确认，接口预留
- 堡垒机/优维 Agent 通道：二期依赖，首期仅做抽象预留

## Assumptions Challenged

| Assumption | Challenge Tool | Finding |
|------------|---------------|---------|
| 核心需求是"自动续签" | XY Problem Detection | Overturned：EV/OV 付费证书无法 ACME 自动签发，真实需求是"签发后自动更换到所有引用点"，供应模型定为纯托管导入 |
| 需要新建独立平台（前后端全新） | Occam's Razor / 简单替代 | Refined：e-cam 已具备账号凭证、资产同步、任务框架、权限体系，作为新功能域成本远低于独立平台 |
| Nginx 管理需要在服务器装 Agent | Stress Test | Refined：平台不能直连服务器；首期用 TLS 探测零侵入覆盖到期监控，更换走可插拔通道（首期堡垒机方向预留、优维 Agent 备选），不引入自研 Agent |
| 换证应全自动无人工介入 | Assumption Flip | Overturned：生产 CDN/WAF/LB/网关批量变更风险高，定为"一键批量 + 人工确认 + 可回滚" |

## Scope

### In Scope（首期）

1. 证书托管台账：导入（证书+私钥）、列表/详情/删除、要素解析（SAN/签发者/有效期）、私钥加密存储
2. 完整性检查：证书/私钥匹配、证书链完整性、SAN 覆盖、有效期校验；导入拦截 + 定时巡检
3. 引用关系发现（只读，全云）：阿里云/腾讯云/华为云/AWS/Azure 的 CDN/DCDN/WAF/LB 证书引用扫描；多云 K8s 网关 CRD 证书引用扫描；与托管证书关联形成"证书 → 资源"视图与反向查询
4. 到期监控与告警：按子域名到期看板、30/14/7 天分级告警、webhook + 邮件渠道
5. TLS 主动探测：对托管子域名端点定期握手探测线上生效证书，与台账比对，差异告警
6. 一键批量更换：新证书导入后自动生成同域名旧证书的变更清单 → 人工确认 → 批量执行 → 逐项进度 → 失败回滚 → 变更报告
7. 首期部署器：阿里云、腾讯云的 CDN/DCDN/WAF/ALB(LB)（含"上传到云证书库 + 绑定资源"两段式）；多云 K8s 集群网关 CRD 证书引用更新（仅 patch 证书引用字段，保留原值记录）
8. 执行通道抽象：云 API 通道、K8s API 通道实现；堡垒机通道、优维 Agent 通道接口预留
9. 权限与审计：接入 EIAM；变更操作全量审计日志
10. 前端（e-cam-web）：证书管理页面（台账、引用关系、到期看板、变更向导与报告）

### Out of Scope（明确延期）

- 华为云、AWS、Azure 的证书更换部署器（二期；首期这三家只做引用发现与到期监控）
- VM Nginx 的配置级引用发现与证书推送更换（依赖堡垒机/优维 Agent 通道，二期；首期 Nginx 仅 TLS 探测监控）
- ACME 自动签发、证书供应商 API 自动续费下单（与 EV/OV 采购模式不符，如未来部分域名转免费证书再评估）
- 更换前的多人审批流（首期为单人确认）
- K8s Secret 直管证书（当前场景为 CRD 引用云托管证书，无此需求）

## Key Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 各云证书绑定 API 差异/限制（部分产品只认云托管证书 ID、接口能力不一） | H | H | 部署器统一"两段式"设计（先上传云证书库再绑定）；任务分解中先做逐云 API 能力验证（PoC）再开发 |
| 私钥泄露（集中存储成为高价值目标） | L | H | 私钥加密存储、接口与前端永不返回明文、EIAM 细粒度权限、访问审计 |
| 批量更换引发生产事故（证书文件错误、绑定失败导致业务中断） | M | H | 人工确认 + 完整性前置校验、分批执行、失败项自动保留旧引用并可回滚、TLS 探测事后验证、变更报告 |
| 多云 K8s 集群接入与 CRD 变更风险 | M | M | 仅 patch 证书引用字段、更新前记录原值、集群不可达时跳过并报告 |
| 二期堡垒机自动化 API 受限，VM Nginx 更换通道受阻 | M | M | 通道抽象预留优维 Agent 备选实现路径；首期不依赖 |
