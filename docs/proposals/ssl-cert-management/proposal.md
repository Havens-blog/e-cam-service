# Proposal: SSL 证书统一托管与更换平台（e-cam 证书管理功能域）

## Problem

多云环境（阿里云/腾讯云/华为云/AWS/Azure）下的 SSL 证书更换目前是纯手工操作：每张证书到期需要在多云的 DCDN/CDN、WAF、ALB/CLB/NLB、多云 K8s 自建网关（ALBConfig 等 CRD）、约 150 台 VM Nginx 上逐处更换，没有统一台账，无法清晰看到各子域名证书的到期时间，也无法回答"这张证书被哪些资源引用"。换证频繁（付费证书周期短）且极易漏换，漏换即线上 HTTPS 事故。

### Evidence

- 证书来源为外部付费平台购买的 EV/OV 证书，无法通过 ACME 自动签发，签发环节只能人工完成
- 引用点多且分散：多云 DCDN/CDN、多云 WAF、多云 ALB/LB、多云 K8s 集群自建网关（通过 ALBConfig 等 CRD 引用云上托管证书 ID）、约 150 台多云 VM 上的 Nginx
- 现状操作路径示例（K8s 网关）：进入集群 → 工作负载 → 自定义资源 → 编辑 ALBConfig → 手工把旧证书 ID 换成新证书 ID——每次换证全网重复此类操作十几处
- 无统一台账：无法按子域名查看证书到期时间、无到期预警、无证书文件完整性检查、无引用关系视图
- 量化量级（以初始导入盘点为准校准）：多云 + 约 150 台 VM 规模下，存量在用 EV/OV 证书为数十张量级；每张年签即年均数十轮换证，每轮涉及十几处引用点手工操作，年均高危手工操作达数百次；历史漏换/临期事件次数在初始导入时从各云控制台与告警记录回溯量化补录

### Urgency

每轮换证都是一次全网高危人工变更，成本高、周期长、易漏；随着引用点数量增长，漏换导致生产事故的风险持续累积。当前无任何系统化支撑，每延迟一轮证书周期就多承受一轮全网手工变更风险。

## Proposed Solution

在 e-cam 平台（后端 e-cam-service / 前端 e-cam-web）新增**证书管理功能域**，围绕"人工购买 → 平台托管 → 自动发现引用 → 一键批量更换 → 验证生效"闭环：


1. **证书托管台账**：导入证书文件（证书 + 私钥），私钥加密存储；列表/详情/删除（删除非零拦截：存在活跃引用或处于回滚保护期内的证书禁止删除，需先解除引用或经强制二次确认）；解析证书的域名（SAN）、签发机构、有效期等要素
2. **完整性检查**：导入及巡检时校验证书/私钥匹配、证书链完整性、SAN 域名覆盖、有效期；与线上实际生效证书比对

3. **引用关系发现**：基于已有云账号与资产同步能力，只读扫描多云 CDN/DCDN/WAF/LB 的证书引用；扫描多云 K8s 集群的网关 CRD 中的证书引用；与平台托管证书按证书指纹关联，形成"证书 → 资源"反向视图。每次扫描记录扫描时间与资源覆盖率元数据（本次扫描覆盖了哪些云/产品/集群），引用视图与变更清单据此显式声明覆盖边界——首期视图不含 VM Nginx 的配置级引用，页面明确标注该盲区，避免"全部引用"误导
4. **到期监控与告警**：按子域名的到期时间看板 + 分级告警（30/14/7 天）+ TLS 主动探测（对各子域名端点握手读取线上实际生效证书，无需接入服务器即可覆盖 Nginx 场景的到期监控）

5. **一键批量更换**：导入新证书后按证书指纹（而非域名）匹配同一旧证书的全部引用点，通配符与多 SAN 证书按证书粒度建模（一张证书生成一张清单，同域名并存的多张证书互不误伤）；变更清单生成强制绑定最近一次扫描结果，扫描超出设定新鲜度阈值（如超过 24 小时未完成新一轮扫描）则阻断清单生成并提示先执行扫描；流程为：变更清单 → 人工确认 → 批量执行（首期覆盖阿里云、腾讯云全套 CDN/DCDN/WAF/LB 部署器 + 多云 K8s CRD 证书引用更新）→ 逐项进度 → 失败可回滚 → 变更后验证 → 变更报告。回滚语义：仅回滚本次变更涉及的资源；执行回滚前先校验回滚目标有效性（旧证书引用仍存在且未过期——指该云证书库中的旧证书仍存在且未过期；云侧证书库中的旧证书已被删除或已过期时不自动回滚，明确提示进入人工决策，平台侧旧证书因非零引用拦截本就不会在此阶段被删除）；回滚自身失败的项立即告警并转人工介入。变更后验证：批量更换后进入有限时长的验证窗口，TLS 探测按变更清单的预期终态（含部分成功的分裂状态）比对，窗口内差异以"变更关联告警"呈现而非普通差异告警，避免告警噪声淹没真实异常；窗口关闭或全部达标后恢复正常告警规则。两个时间窗的量级口径：验证窗口为小时级量级（如 2~24 小时）；回滚保护期为天级量级（如 7~14 天），自变更完成起算且不短于验证窗口，保护期内该旧证书在平台的删除操作被拦截；具体数值留 tech-design
6. **可插拔执行通道**：变更执行与目标资源之间通过通道抽象解耦——云 API 通道、K8s API 通道首期实现；堡垒机通道（VM Nginx）、优维 Agent 通道预留接口二期实现

### Innovation Highlights

- **引用关系自动发现**是本方案区别于行业方案的核心能力：Certimate/Certd 等开源工具只能管理"自己部署过的"证书，无法发现存量资源已经引用的证书；本方案基于 e-cam 已有的多云账号凭证与资产同步框架，可对存量全网引用做只读发现并建立反向视图
- **可插拔执行通道**适配企业网络现实：平台不能直连 Nginx 服务器，执行通道抽象使"堡垒机 → 优维 Agent"的演进不改变上层更换逻辑
- **TLS 主动探测**用零侵入方式覆盖 Nginx 到期监控：不装 Agent、不走堡垒机，握手即可读取线上生效证书并与台账比对
- 其余为证书管理领域的标准做法（台账、加密存储、完整性校验、批量变更），属于常规采用，不另作创新声明

## Requirements Analysis

### Key Scenarios

**Happy path**
- 运维导入新购证书（PEM + 私钥）→ 系统校验通过、解析要素、加密入库
- 存量证书初始导入（bootstrap）：上线前对全网在用证书批量补录——证书文件与私钥从各引用方/原持有人定向回收后批量导入；无法回收私钥的存量证书支持"仅指纹登记"（参与指纹关联、引用视图与到期监控，但该证书更换前必须补齐私钥并明确提示）；以"台账指纹覆盖率（已入台账证书 / 引用扫描发现的在用证书）"度量初始导入完整率
- 运维查看某域名证书 → 看到全部引用资源（多云 CDN/WAF/LB、K8s 网关 CRD）
- 到期看板按子域名展示剩余有效期；30/14/7 天分级告警推送

- 换证：导入新证书 → 系统按证书指纹列出同一旧证书全部引用点及计划动作（绑定最近扫描，陈旧扫描被阻断）→ 人工确认 → 批量执行 → 逐项成功/失败状态 → 变更报告 → 变更后验证窗口内 TLS 探测按预期终态比对线上生效证书

**边界场景**
- 导入的证书与私钥不匹配 / 证书链缺失 / SAN 不含预期域名 → 拦截并明确报错
- 同一域名存在多张未过期证书（新旧并存）→ 引用视图按实际引用区分展示

- 生成变更清单时引用扫描数据已超出新鲜度阈值 → 阻断清单生成，提示先完成新一轮扫描

- 通配符证书 / 一张证书覆盖多个 SAN 域名 → 按证书指纹聚合为一张变更清单，不影响同域名并存的其他证书的引用

- 证书已导入但引用发现尚未扫描到 → 标记"未发现引用"而非视为无引用，且引用视图标注"不含 VM Nginx 配置级引用"

- 探测发现线上生效证书与平台台账不一致 → 差异告警；若处于变更后验证窗口内且与变更清单预期终态一致（含部分成功分裂状态）→ 以变更关联告警呈现，不触发常规差异告警

**错误场景**

- 批量更换中部分资源执行失败 → 失败项保留旧证书引用并可一键回滚（回滚前校验旧证书引用仍有效，已删除/已过期则转人工决策），已成功项出具明细

- 两段式上传中第二段（绑定资源）失败 → 记录"已上传至云证书库但未绑定"的中间态并补偿：绑定重试仍失败时，依据平台证书 ↔ 云证书 ID 映射表回收/清理本次产生的未绑定云侧证书，避免孤儿证书累积占用托管配额

- K8s CRD patch 后被 GitOps/控制器 reconcile 回写覆盖 → 更新前先探测资源管理权（是否 GitOps 管理、是否有控制器拥有该字段），有冲突管理权的目标标记"不可自动变更"并提示走其管理链路；已执行的目标在变更后复检引用是否仍为新证书，被回写覆盖则告警
- 回滚自身执行失败 → 立即告警并转人工介入，变更报告如实记录该项回滚失败
- K8s 集群不可达 / CRD 更新冲突 → 记录失败原因，不阻塞其他目标执行
- 云 API 限流 → 退避重试，超限后标记失败并在报告中体现

### Non-Functional Requirements


- **安全**：私钥加密存储，加密密钥独立于业务数据管理（具体选型留 tech-design）；私钥仅在完整性校验、上传云证书库等必要环节于内存中解密使用，使用后即释放，不落盘、不写入日志与变更报告；任何接口与前端不得返回明文私钥；证书变更全部留审计记录；权限接入现有 EIAM 统一权限体系
- **可靠性**：批量变更逐项隔离，单点失败不影响整体；可回滚
- **及时性**：到期告警按天级巡检触发；变更执行进度实时可见
- **可扩展性**：新增云厂商部署器 / 新执行通道不改上层流程
- **备份与恢复**：私钥库、台账与映射表定期备份，加密密钥另有安全备份机制；平台自身数据丢失不得导致 EV/OV 私钥不可恢复（重新购买证书无法恢复旧私钥）；量级口径为备份周期天级、恢复时间小时级，具体方案与指标留 tech-design
- **容量与性能**：按托管证书百张量级、引用点数千量级设计；单轮全量引用扫描分钟到小时级完成，批量变更逐项进度可见；具体性能指标随 tech-design 定值

### Constraints & Dependencies

- EV/OV 证书无法自动签发：签发（购买）环节永远在平台外部，平台起点是"导入"
- 平台不能直连 VM Nginx：首期 Nginx 仅 TLS 探测监控，配置级引用发现与更换依赖二期执行通道（堡垒机/优维 Agent）
- 部分云产品仅接受"云上托管证书"：更换需两段式（先上传到该云证书库，再绑定资源），各云证书库 API 能力需逐云验证
- 多云 K8s 集群需平台具备接入凭证与 CRD 读写权限
- 依赖已有能力：云账号凭证管理、资产同步框架、异步任务框架、EIAM 权限（均已存在）
- TLS 探测的可达性假设：子域名端点需可从平台网络可达（公网解析或平台可路由）；仅内网解析、平台永久不可达的子域名在台账中标记"探测豁免"，单列清单维护、不参与常规差异告警与不可达告警，但保留到期看板与到期分级告警覆盖

## Alternatives & Industry Benchmarking

### Industry Solutions

- [Certimate](https://github.com/certimate-go/certimate)：开源 ACME 工具，申请/部署/续期/监控全流程，面向自动签发场景
- [Certd](https://github.com/certd/certd)：开源证书申请+部署自动化，阿里云 CDN/DCDN/WAF/SLB 插件生态成熟
- [AllinSSL](https://allinssl.com/)：证书全生命周期管理，多 CA
- 阿里云[证书托管服务](https://help.aliyun.com/zh/ssl-certificate/deploy-ssl-certificates-to-alibaba-cloud-services)：付费托管额度，仅覆盖阿里云产品
- 企业级 CLM 商业平台（Venafi、Keyfactor 类）：私钥托管、证书引用发现与自动化更换、审批流、审计的企业级证书生命周期管理基线

### Comparison Table

| Approach | Source | Pros | Cons | Verdict |
|----------|--------|------|------|---------|
| Do nothing | — | 无成本 | 每轮换证全网高危手工变更，漏换即事故，随引用点增长风险持续上升 | Rejected: 痛点明确且随规模恶化 |
| 纯用开源工具（Certimate/Certd） | 开源社区 | 免费、部署器成熟、开箱即用 | 核心面向 ACME 自动签发，与 EV/OV 人工签发模型不符；无存量引用关系发现；独立账号体系与权限，不融入 EIAM/e-cam | Rejected: 无法覆盖核心场景（引用发现 + 存量更换）|
| 混合：开源工具管续签 + e-cam 只做监控 | 社区 + 自建 | 各取所长 | 两套系统两套凭证，用户跨平台操作；开源工具对 EV/OV 导入更换支持有限 | Rejected: 体验割裂且核心痛点仍在 |
| 企业级 CLM 商业平台（Venafi/Keyfactor） | 商业软件 | 成熟的私钥托管、审批流与审计，Venafi 具备 Orchestrator 级部署发现能力，可作能力基线 | 企业授权成本高、部署与集成重；对国内云（阿里/腾讯/华为）部署器覆盖有限；独立账号体系，不融入 EIAM 与现有多云凭证管理 | Rejected: 采购成本与国内多云覆盖不满足；其"发现→托管→更换"能力框架作为自建方案的对标基线 |
| **自建 e-cam 证书管理功能域** | 本提案 | 复用云账号凭证/资产同步/任务框架/权限体系；存量引用关系发现为独有能力；执行通道抽象适配堡垒机→Agent 演进 | 部署器需自研，工作量大，需分期 | **Selected: 唯一能同时满足"引用发现 + EV/OV 托管更换 + 权限一体化"的路线** |

> Challenge Override 记录：需求闸门提出"开源工具是更简单替代方案"，用户选择自建。理由：开源工具无法发现存量资源的证书引用，且无法融入现有权限与账号体系。

## Feasibility Assessment

### Technical Feasibility

- 后端全部依赖已就绪：云账号 AK/SK 管理、多云 SDK 适配层（已有 6 云接入）、CDN/LB/WAF 同步器已采集证书名字段、异步任务框架、EIAM 权限
- 证书解析/校验、TLS 探测为成熟技术领域，无技术阻塞
- 风险点在各云证书绑定 API 的差异与限制，需逐云做 API 能力验证（PoC 性质任务列入任务分解）

### Resource & Timeline

首期范围（双云部署器 + 全量监控）为可控的分期切分，依据如下：新增量集中在证书域本身（2 家云 4 类部署器、5 家云只读扫描器、K8s CRD patch、TLS 探测、前端 4 类页面），底座能力（多云 SDK 适配、凭证、任务框架、权限）全部复用零新建；团队即 e-cam 现有后端团队，具备 6 云 SDK 适配与资产同步框架的交付经验，无新技能引入。参照 e-cam 既有功能域（多云接入、资产同步）按季度级节奏交付的历史，首期工作量量级估计为 1~2 名后端 + 1 名前端、1~2 个季度；其中各云证书绑定 API 验证（PoC）为前置里程碑。精确估算与排期在 tech-design 阶段给出。

### Dependency Readiness

- 云账号凭证：已有 ✅
- 多云 K8s 集群接入凭证：**待准备**（需采集各集群的访问凭证并授权 CRD 读写）

- 告警渠道（webhook + 邮件）：通道待确认，接口预留；渠道确认为 PRD 前置依赖，确认完成前**所有依赖告警渠道的成功标准**（到期分级告警、TLS 差异告警、变更关联告警、回滚失败告警）均不进入验收，门控口径统一，不单独豁免任何一项
- 堡垒机/优维 Agent 通道：二期依赖，首期仅做抽象预留

## Assumptions Challenged

| Assumption | Challenge Tool | Finding |
|------------|---------------|---------|
| 核心需求是"自动续签" | XY Problem Detection | Overturned：EV/OV 付费证书无法 ACME 自动签发，真实需求是"签发后自动更换到所有引用点"，供应模型定为纯托管导入 |
| 需要新建独立平台（前后端全新） | Occam's Razor / 简单替代 | Refined：e-cam 已具备账号凭证、资产同步、任务框架、权限体系，作为新功能域成本远低于独立平台 |
| Nginx 管理需要在服务器装 Agent | Stress Test | Refined：平台不能直连服务器；首期用 TLS 探测零侵入覆盖到期监控，更换走可插拔通道（首期堡垒机方向预留、优维 Agent 备选），不引入自研 Agent |
| 换证应全自动无人工介入 | Assumption Flip | Overturned：生产 CDN/WAF/LB/网关批量变更风险高，定为"一键批量 + 人工确认 + 可回滚" |

## Scope

### In Scope（首期）


1. 证书托管台账：导入（证书+私钥）、列表/详情/删除（被引用或回滚保护期内的证书拦截删除）、要素解析（SAN/签发者/有效期）、私钥加密存储
2. 完整性检查：证书/私钥匹配、证书链完整性、SAN 覆盖、有效期校验；导入拦截 + 定时巡检

3. 引用关系发现（只读，全云）：阿里云/腾讯云/华为云/AWS/Azure 的 CDN/DCDN/WAF/LB 证书引用扫描；多云 K8s 网关 CRD 证书引用扫描；与托管证书按证书指纹关联形成"证书 → 资源"视图与反向查询；每次扫描记录扫描时间与资源覆盖率元数据，视图与变更清单声明覆盖边界（首期不含 VM Nginx 配置级引用）
4. 到期监控与告警：按子域名到期看板、30/14/7 天分级告警、webhook + 邮件渠道
5. TLS 主动探测：对托管子域名端点定期握手探测线上生效证书，与台账比对，差异告警

6. 一键批量更换：新证书导入后按证书指纹匹配同一旧证书（含通配符/多 SAN 证书）生成变更清单（强制绑定最近扫描，扫描超期阻断生成）→ 人工确认 → 批量执行 → 逐项进度 → 失败回滚（范围限本次变更项，回滚前校验旧证书引用有效性，回滚失败告警转人工）→ 变更后验证窗口（TLS 探测按预期终态比对，含部分成功分裂状态，与常规差异告警区分）→ 变更报告

7. 首期部署器：阿里云、腾讯云的 CDN/DCDN/WAF/ALB(LB)（含"上传到云证书库 + 绑定资源"两段式，第二段失败时依据映射表补偿清理未绑定的云侧孤儿证书）；多云 K8s 集群网关 CRD 证书引用更新（仅 patch 证书引用字段，保留原值记录；更新前探测资源管理权，变更后复检防 reconcile 回写）

8. 云证书映射表：维护"平台托管证书 ↔ 各云证书库证书 ID"映射，作为两段式上传去重、回滚定位与孤儿证书清理的基础数据
9. 执行通道抽象：云 API 通道、K8s API 通道实现；堡垒机通道、优维 Agent 通道接口预留
10. 权限与审计：接入 EIAM；变更操作全量审计日志
11. 前端（e-cam-web）：证书管理页面（台账、引用关系、到期看板、变更向导与报告）

### Out of Scope（明确延期）


- 华为云、AWS、Azure 的证书更换部署器（二期；首期这三家只做引用发现与到期监控——存在"看得到却换不了"的运营窗口，窗口内到期证书仍需手工更换，靠到期看板与分级告警兜底提醒）
- VM Nginx 的配置级引用发现与证书推送更换（依赖堡垒机/优维 Agent 通道，二期；首期 Nginx 仅 TLS 探测监控）
- ACME 自动签发、证书供应商 API 自动续费下单（与 EV/OV 采购模式不符，如未来部分域名转免费证书再评估）
- 更换前的多人审批流（首期为单人确认；补偿控制边界：变更前完整性校验 + 指纹精确匹配 + 扫描新鲜度阻断共同缩小误操作面，批量执行支持分批灰度（单批引用点占比上限的量级为不超过一半，首批更小，具体值留 tech-design），失败自动保留旧引用可回滚兜底；发起权限收敛到 EIAM 指定角色并全量审计，使单人确认的风险敞口限制在"已知清单内的确定性变更"）
- K8s Secret 直管证书（当前场景为 CRD 引用云托管证书，无此需求）

## Key Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 各云证书绑定 API 差异/限制（部分产品只认云托管证书 ID、接口能力不一） | H | H | 部署器统一"两段式"设计（先上传云证书库再绑定）；任务分解中先做逐云 API 能力验证（PoC）再开发 |
| 私钥泄露（集中存储成为高价值目标） | L | H | 私钥加密存储、接口与前端永不返回明文、EIAM 细粒度权限、访问审计 |
| 批量更换引发生产事故（证书文件错误、绑定失败导致业务中断） | M | H | 人工确认 + 完整性前置校验、分批执行、失败项自动保留旧引用并可回滚、TLS 探测事后验证、变更报告 |

| 多云 K8s 集群接入与 CRD 变更风险（含 GitOps/控制器 reconcile 回写覆盖 patch） | M | M | 仅 patch 证书引用字段、更新前探测资源管理权并记录原值、变更后复检、集群不可达时跳过并报告 |

| 两段式上传第二段失败产生云侧孤儿证书，累积占用托管配额 | M | M | 平台证书 ↔ 云证书 ID 映射表 + 绑定重试失败后的补偿清理 + 孤儿证书定期巡检清理 |

| 华为云/AWS/Azure 首期只发现不更换，"看得到却换不了"的运营风险窗口（期间这三家云上证书到期仍需手工更换） | M | M | 二期排期与引用点增长绑定；窗口期以到期看板 + 分级告警 + TLS 探测兜底提醒手工更换，Out of Scope 中显式声明该窗口 |
| 二期堡垒机自动化 API 受限，VM Nginx 更换通道受阻 | M | M | 通道抽象预留优维 Agent 备选实现路径；首期不依赖 |

## Success Criteria

- [ ] 导入环节 100% 拦截证书/私钥不匹配、证书链缺失的文件，并给出明确错误提示

- [ ] 引用关系发现覆盖 5 家云（阿里/腾讯/华为/AWS/Azure）的 CDN/DCDN/WAF/LB 与多云 K8s 网关 CRD；抽样人工核对一致率 ≥ 95%（该指标表征查准：发现的引用真实存在），且各云各产品扫描覆盖率 ≥ 99%（以云侧可见资源总数为分母，表征查全：未扫到的资源占比 ≤ 1%）

- [ ] 变更清单生成 100% 绑定最近一次引用扫描：扫描超出新鲜度阈值时清单生成被阻断；引用视图与变更清单均显示扫描时间与覆盖边界（不含 VM Nginx 配置级引用）

- [ ] 到期看板展示全部托管子域名证书的到期时间，30/14/7 天三级告警按已配置渠道触达（受告警渠道门控，见依赖段）

- [ ] 阿里云、腾讯云 CDN/DCDN/WAF/LB 一键更换批量执行成功率 ≥ 95%；失败项回滚前校验目标有效性，云证书库中旧证书仍存在且未过期的项回滚成功率 100%，云侧旧证书已删除/已过期的项不自动回滚且 100% 记录人工决策结果

- [ ] 多云 K8s CRD 证书引用更新成功率 ≥ 95%，每次更新保留变更前值，且变更后复检确认引用未被 reconcile 回写覆盖（被覆盖项告警）
- [ ] TLS 探测覆盖全部未豁免的托管子域名端点（内网不可达的豁免端点单列清单、不计入覆盖分母；非豁免端点不可达时单独标记并告警，不计为覆盖失败），能识别线上生效证书与台账不一致并告警（受告警渠道门控，见依赖段）
- [ ] 完整性定时巡检按天级周期自动执行，巡检发现的证书/私钥不匹配、证书链缺失、临期项 100% 产生巡检记录并按规则告警（受告警渠道门控，见依赖段）
- [ ] 孤儿证书治理有效：补偿清理后仍存在的云侧孤儿证书在定期巡检中被识别并 100% 列入孤儿清单，人工确认后清理并在映射表注销记录
- [ ] 执行通道可插拔性可验证：以接入一个测试用模拟执行通道完成端到端更换演示，上层更换流程（清单生成/确认/进度/回滚/报告）零代码改动
- [ ] 处于回滚保护期内的证书执行删除操作 100% 被拦截，拦截提示注明保护期截止时间
- [ ] 初始导入完成后，台账对引用扫描发现的在用证书的指纹覆盖率 ≥ 90%，未入库与"仅指纹登记"的证书在页面单列清单可见
- [ ] 前端交付四类页面（证书台账、引用关系、到期看板、变更向导与报告），并支撑一次端到端换证演示（导入 → 清单 → 确认 → 执行 → 报告全程在页面完成）
- [ ] 私钥全程加密存储，任何接口/页面均无法获取明文私钥（自查口径：由安全评审按检查单执行，覆盖 API 响应、日志、变更报告、前端网络请求与浏览器本地存储均无明文私钥，检查单与结果留档）
- [ ] 每次更换生成完整变更报告（清单、逐项结果、回滚状态），并留有全量审计记录
