# 2.2: 导入服务与 API（单张+批量+补传私钥升级、重复指纹 409、expectedDomain 提示比对、batchId 会话、进度轮询）

## Description
证书导入服务与 HTTP 端点：单张导入（multipart certFile+可选 keyFile+可选 expectedDomain）、批量导入（CertBatchSession 会话 + 逐文件隔离 + 进度轮询）、补传私钥升级完整托管。响应统一信封，私钥永不返回。API 前缀 `/api/v1/certs`。

## Acceptance Criteria
- [ ] `POST /api/v1/certs`：multipart 上传，成功 200 `{certId, fingerprint, hostingStatus}`；有 keyFile → complete（私钥经 1.1 信封加密存储），无 keyFile → fingerprint_only；expectedDomain 与 SAN 比对不一致 → 响应附提示字段，不拦截。
- [ ] 校验失败映射：CERT_KEY_MISMATCH/CERT_CHAIN_INCOMPLETE/CERT_PARSE_FAIL → 400；重复指纹 → 409 CERT_DUPLICATE_FINGERPRINT；逐项错误码与 api-handbook 一致。
- [ ] `POST /api/v1/certs/batch` → 202 `{batchId, status, files[], progress}`；batchId=cert_batch_sessions._id；逐文件独立校验入库，单文件失败不阻塞其他文件（失败行含 errorReason，可单独重试=重新 POST 单文件）。
- [ ] `GET /api/v1/certs/batch/:batchId` → 同构响应；终态 completed/partial_failed；progress{total,done,failed} 随文件完成原子递增；会话 TTL 30 天由索引承接。
- [ ] `POST /api/v1/certs/:id/key`：补传私钥 → 2.1 匹配校验通过后升级 hostingStatus=complete（加密落库）；不匹配 → 400 CERT_KEY_MISMATCH。
- [ ] httptest 契约测试：单张四类拦截、批量混合成败、轮询到终态、补传升级；所有响应断言无明文私钥/密文字段。

## Hard Rules
- 任何响应/日志不返回明文私钥与 encryptedPrivateKey 密文；导入成功响应仅含 certId/fingerprint/hostingStatus。
- 批量导入逐文件隔离：一个文件解析 panic/失败不得中断会话（recover + errorReason 落档）。

## User Stories
Story 1（导入新购证书）、Story 4（存量证书初始导入 + 补传私钥升级完整托管）。
