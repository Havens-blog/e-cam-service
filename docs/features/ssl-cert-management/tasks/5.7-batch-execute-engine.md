# 5.7: 批量执行引擎（任务框架子任务派发、心跳 heartbeatAt、executing-timeout、rate_limited 退避上限→failed、分批 floor(total/2) 门控、ConfirmBatch）

## Description
ChangeService 的执行编排：Confirm（批次分配固化 + 快照重校验）、Execute（internal/task 派发子任务执行当前批）、逐项隔离（单项失败不阻塞其他项）、30s 心跳、executing-timeout 恢复函数、rate_limited 退避上限收敛 failed、ConfirmBatch 人工续批门控（上一批全部 success 且批级验证达标，否则 409 BATCH_NOT_CONFIRMABLE）、订单状态按剩余项重算。

## Acceptance Criteria
- [ ] Confirm(orderId, batchConf)：快照确认时点重校验（新鲜度/引用一致性）；批次分配一次性固化——items 按 (cloud,product,resourceId) 字典序稳定排序，首批=min(BatchSize, floor(total/2))，余下按 BatchSize 均分（末批可不足额），逐项写 batchNo；batchInfo{totalBatches,currentBatch,batchSize,paused,pausedAt}；MaxBatchRatio ≤0.5 硬校验。
- [ ] Execute(orderId)：派发子任务仅执行 batchNo=currentBatch 的项；子任务仅凭持久化 resourceRef 重构 DeployTarget（不回查台账/快照）；逐项隔离（单项 panic/失败 recover 并落项级状态）。
- [ ] 心跳：执行期 30 秒间隔更新 ChangeItem.heartbeatAt；`RecoverTimedOutItems()`（executing-timeout 恢复函数）扫 running 且心跳超 itemHeartbeatTimeoutMinutes → failed(EXEC_TIMEOUT) + 告警 + 单据状态重算。
- [ ] rate_limited：项遇 CLOUD_API_RATELIMITED → status=rate_limited 退避重试；退避上限耗尽 → failed；进度轮询可见"限流重试中"。
- [ ] ConfirmBatch(orderId)：仅当上一批全部 success 且批级验证达标（提频探测连续 verifyConfirmProbes 一致，判定由 5.10 提供）→ currentBatch+1 放行；否则 409 BATCH_NOT_CONFIRMABLE；批间暂停 batchInfo.paused=true/pausedAt=now。
- [ ] 每项终态变更后按剩余项重算订单状态（executing↔verifying 循环、终态收敛）；集成测试：批次分配（含 floor(total/2) 上限）、部分失败隔离、心跳超时恢复、续批门控 409。

## Hard Rules
- 单批 ≤ floor(total/2) 为硬约束（PRD 分批灰度 ≤50%），越界 Confirm 拒绝。
- 执行期间清单快照固定不变：不得因新扫描结果增删 ChangeItem。
- 分批一律人工续批，不提供自动续批。
