# 6.1: 前端模块脚手架（cert 路由注册、菜单、EIAM 权限、只读角色路由拦截、api client 封装）

## Description
e-cam-web 新增证书管理路由模块：7 条路由注册（/certs、/certs/:id、/certs/dashboard、/certs/changes、/certs/changes/new、/certs/changes/:id、/certs/settings）、一级菜单"证书管理"（台账/看板/变更管理）、EIAM 三角色可见性、只读角色路由拦截（仅看板+详情可见）、统一 api client 封装（信封解包+类型定义）。页面组件为占位页，6.2-6.6 填充。

> 跨仓库任务：文件位于 e-cam-web 仓库（D:\Haven\e-cam-web），下述路径均为 e-cam-web 仓库相对路径。设计文档表述为"views/modules/cert"，实际按 e-cam-web 现有约定落地为 `src/views/cert/`（与 views/cam、views/assets 平级）。

## Acceptance Criteria
- [ ] `src/router/routes.ts` 注册 7 条路由（懒加载 + meta.title/icon，二级页 hideInMenu）：/certs、/certs/:id、/certs/dashboard、/certs/changes、/certs/changes/new、/certs/changes/:id、/certs/settings。
- [ ] 一级菜单"证书管理"分组下展示 证书台账/到期看板/变更管理 三项（沿用现有菜单机制，按 EIAM 角色控制可见性）。
- [ ] 只读角色：仅见"到期看板"菜单；/certs、/certs/changes*、/certs/settings 直接访问被前端拦截提示"无权限访问，仅到期看板可见"；/certs/dashboard 与 /certs/:id 对只读开放。
- [ ] `src/api/cert.ts`：覆盖 cert 全部端点的类型化 client（请求经现有 request 封装，响应解 `{success,data,error,meta}` 信封），类型定义含 ChangeOrder/ChangeReport/ProbeResult/CertReference 等枚举全集。
- [ ] `src/views/cert/` 模块骨架建立（每页面一个占位 index.vue + 目录），构建通过：`npm run build`（或等价 type-check/build 脚本）无错误。

## Hard Rules
- 路由拦截必须前端+后端双侧（前端拦截仅为体验层，接口由 EIAM 同步拦截——本任务只做前端层）。
- 不修改既有模块路由/菜单行为（additive 注册）。

## User Stories
Story 6（只读查看者路由可见性 AC）、间接支撑全部 UF 导航。

## Implementation Notes
- 跨仓库（e-cam-web）：修改 `src/router/routes.ts`、新增 `src/api/cert.ts`、`src/api/types/cert.ts`（类型可并入 cert.ts 视现有 api 目录约定）、`src/views/cert/{ledger,detail,dashboard,changes,settings}/index.vue` 占位。
- 角色判定复用现有用户 store/EIAM 角色机制（src/stores、src/api/eiam-mapper.ts）；拦截以路由守卫或 meta 权限字段实现，与现有页面一致。
- dev 联调可指向 e-cam-service 本地启动地址（现有 request 封装的 baseURL 机制）。
