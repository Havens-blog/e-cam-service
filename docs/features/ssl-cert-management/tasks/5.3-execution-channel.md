# 5.3: ExecutionChannel 抽象与 CloudAPIChannel（接口定义、Credential/DeployTarget 载荷、两段式编排、模拟通道）

## Description
定义 ExecutionChannel 接口（Discover/Deploy/Rollback/Type）与 Service-Level Types（Credential/DiscoverScope/DeployTarget/DeployResult/RollbackResult/CloudCertInfo/BatchConf），实现 CloudAPIChannel（两段式 UploadCert→BindResource + 第二段失败 CleanupOrphan 补偿 + CloudCertMapping 写入 + OrphanCandidate 标记）与 SimulatedChannel（mock 通道，验证可插拔性零上层改动）。bastion/agent 接口预留（仅 Type 常量）。

## Acceptance Criteria
- [ ] `ExecutionChannel` 接口定义 Discover/Deploy/Rollback/Type，ChannelType 常量 cloud_api/k8s_api/bastion/agent；Service-Level Types 字段+类型+约束与 tech-design Service-Level Types 节逐项对齐（Credential.Kind/Cloud/AccountKey/AccessKey/Secret/KeyVersion 等）。
- [ ] CloudAPIChannel.Deploy：两段式 UploadCert→BindResource；成功 → 写 CloudCertMapping{certFingerprint,cloud,accountKey,cloudCertId,status=active}；DeployResult{NewCloudCertID,OldCloudCertID,OrphanCandidate}。
- [ ] 第二段（BindResource）失败 → CleanupOrphan 补偿清理未绑定云侧孤儿证书 + OrphanCandidate=true（供 5.9 队列消费）；映射表状态流转 active→orphan。
- [ ] Credential 解密明文仅内存、用后 zeroing（复用 1.1），永不进日志/响应/审计；DeployTarget 字段按 channel 分支校验必填。
- [ ] SimulatedChannel 实现 ExecutionChannel（mock 成功/失败/限流可配置），用于 e2e 演示"堡垒机/Agent 通道零上层改动"可插拔性。
- [ ] 单元测试：mock CloudDeployer 覆盖两段式成功/第二段失败补偿/孤儿标记；SimulatedChannel 全路径。

## Hard Rules
- Credential 明文零生命周期：函数返回前 zeroing，禁序列化为 string、禁写入任何结构体字段逃逸。
- ExecutionChannel 接口须容纳 bastion/agent 二期实现而不改签名（仅新增实现）。

## User Stories
Story 3（一键批量更换 — 执行通道抽象与两段式）；可插拔性对应 PRD In Scope 执行通道抽象。
