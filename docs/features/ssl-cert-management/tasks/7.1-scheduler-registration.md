# 7.1: 9 个定时任务注册与 ioc/cert wire 装配

## Description
将 cert 功能域的 9 个定时任务挂入 `internal/task` 框架并完成 `ioc/cert.go` Wire 注入装配：scan（天级+手动防重）、scan-timeout（15 分钟扫超时快照转 failed 释放锁）、probe（天级；验证窗口内提频）、inspection（天级）、window-expiry（周期=verifyProbeIntervalMinutes）、pause-timeout（每小时）、orphan-cleanup（天级批扫+事件触发）、crd-recheck（patch 后延迟 recheckDelayMinutes）、executing-timeout（每 5 分钟扫心跳超时项）。本任务为装配收口任务，修改 ioc/wire 共享装配（breaking）。

## Acceptance Criteria
- [ ] 9 个任务全部在 `internal/task` 框架注册，频率/触发按 Scheduler Tasks 表：scan 天级+手动(防重 409)；scan-timeout 每 15 分钟；probe 天级+窗口内提频（周期切换由 5.10 控制，本任务注册天级与提频两个调度点或由 5.10 接管提频）；inspection 天级；window-expiry 周期=verifyProbeIntervalMinutes；pause-timeout 每小时；orphan-cleanup 天级批扫+事件触发；crd-recheck patch 后延迟 recheckDelayMinutes；executing-timeout 每 5 分钟。
- [ ] `internal/cert/module.go` + `ioc/cert.go` 注入：repository/service/deployer/scheduler/web 全量 wire；`wire_gen.go` 重新生成且 app 启动注入 cert 域无报错。
- [ ] 任务入口幂等+并发安全：同一任务不重复并发执行（框架级锁/Redis 锁）；scan/probe/inspection 失败不阻塞其他任务；scan 防重与 scan-timeout 恢复联动（running 超时释放锁后可重新触发）。
- [ ] 既有 `internal/cam` 与其他域任务注册不受影响（不改动既有 task 注册项；新增项独立）。
- [ ] 启动冒烟：app boot 后任务按频率进入排队；manually 触发 scan/inspection 各一次无 panic（mongox test 或开发库）。
- [ ] 频率/阈值参数从 AlertConfig.thresholds 读取（3.5/4.4/5.9/5.10 已提供函数，本任务接调度周期参数注入）。

## Hard Rules
- 修改 ioc/wire 共享装配为破坏性：必须重新生成 wire_gen.go 并保证既有域注入回归通过。
- 任务函数不得内联业务逻辑（仅调度接线，业务逻辑在 3.5/4.4/5.9/5.10 已实现的恢复/Job 函数）。

## User Stories
间接支撑全部 Story（定时巡检/扫描/探测/窗口/孤儿清理/复检/超时恢复的调度承载）。

## Test Impact
> 本任务修改 `ioc/wire.go`、`ioc/wire_gen.go`、`ioc/cert.go`（新增）、`internal/cert/module.go` 共享装配，影响全应用启动注入链路。测试影响：
> - **必跑**：`go build ./...`（注入编译验证）；`go test ./ioc/...`（wire 生成正确性）；`go test ./internal/cam/...` 与 `./internal/task/...`（既有域回归不受影响）；app boot 冒烟（注入启动无错）。
> - **回归范围**：任何依赖 wire 注入的既有域（cam/alert/audit/task）启动路径——确认新增 cert provider 不与既有 provider 冲突（provider 集合去重、Set 回收无重复）。
> - **回归方式**：先 `go generate ./ioc/...`（或等价 wire 生成命令）→ `go build ./...` → 跑既有域单测 → boot 冒烟 → 手动触发 scan/inspection 各一次。
> - **风险**：wire 生成失败 / provider 冲突 / 任务注册 panic 阻断启动——任一发生立即回滚装配并交回依赖任务修正。

## Implementation Notes
- 修改/新增：
  - `ioc/cert.go`（新增，cert 域 provider 集合，风格参考 `ioc/alert.go`/`ioc/audit.go`）
  - `ioc/wire.go`（在 ProviderSet 集合追加 cert providers）
  - `ioc/wire_gen.go`（`go generate` 重新生成，勿手改）
  - `internal/cert/module.go`（域 module 注册 + EnsureIndexes 启动调用 + 9 任务注册挂 internal/task 框架）
- 任务注册风格参考 `internal/cam/scheduler` 与现有 `ioc/jobs.go`（既有任务挂载机制）。
- 提频探测（窗口内 verifyProbeIntervalMinutes）的调度点：由 5.10 在订单进入 verifying 时主动调度，或由本任务注册一个 verifyProbeIntervalMinutes 周期任务统一扫描活跃窗口——实现时任选其一并与 5.10 一致，记录在注释。
