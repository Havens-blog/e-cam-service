# 2.1: 证书解析与完整性校验（x509 解析/私钥匹配/链完整/有效期/SAN/指纹；CERT_* 四错误）

## Description
证书域的纯函数解析与校验组件：PEM → x509 解析（SAN/CN/签发者/序列号/有效期/keyAlgorithm）、SHA256 指纹、私钥匹配（RSA/ECDSA）、证书链完整性、有效期与 SAN 结构校验。产出 4 个领域错误（CERT_KEY_MISMATCH/CERT_CHAIN_INCOMPLETE/CERT_PARSE_FAIL + 指纹重复由仓储层 sentinel 承接），供 2.2 导入服务与 4.4 巡检复检复用。

## Acceptance Criteria
- [ ] `ParseCertAndKey(certPEM, keyPEM []byte) (*ParsedCert, error)`：解析 SAN 列表/CN/issuer/serialNumber/notBefore/notAfter/keyAlgorithm(RSA|ECDSA)/SHA256 指纹（64 位小写 hex）。
- [ ] 私钥匹配：证书公钥与私钥派生公钥比对（RSA 模数/ECDSA 曲线点），不匹配 → `CERT_KEY_MISMATCH`；无私钥 → 走 fingerprint_only 形态（不报错）。
- [ ] 证书链完整性：leaf+中间链可构建验证（自签根或给出链可验证），缺中间链 → `CERT_CHAIN_INCOMPLETE`。
- [ ] 有效期与 SAN 结构：已过期或 SAN 无法解析 → `CERT_PARSE_FAIL`；SAN 覆盖比对 `CheckSANCover(sans []string, expected []string) (missing []string)` 返回缺失清单（仅提示性，不拦截——拦截点在 5.2 预检）。
- [ ] 错误实现 `error` 接口并携带错误码（`Code() string`），message 不含私钥/密文片段。
- [ ] 表驱动测试：Go 标准库现场生成证书夹具（匹配/不匹配私钥、缺链、过期、SAN 异常、多 SAN/通配符 SAN），覆盖四类拦截与通过路径。

## Hard Rules
- 私钥明文仅在函数内比对后即 zeroing（复用 1.1）；任何错误 message/日志不得含私钥或密文片段。
- 解析为纯函数：不访问 DB、不发网络请求（便于 2.2/4.4 复用）。

## User Stories
Story 1（导入新购证书 — 完整性校验与要素解析）、Story 4（存量导入 — 含/不含私钥两种形态）。
