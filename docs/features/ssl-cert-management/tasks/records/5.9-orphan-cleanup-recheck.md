# Task Record: 5.9 孤儿清理与 CRD 复检消费者（orphan-cleanup 队列消费、映射表状态流转、crd-recheck 任务）

## Summary
实现两个异步消费者：(1) OrphanCleanupService 孤儿清理——事件触发 ConsumeOrderQueue（验证窗口达标关闭/终态后即时消费该单清理队列：成功项旧云证书映射 active→orphan 入队后，逐项清理该单 old/new 两指纹全部 orphan 映射）+ 天级批扫 SweepOrphans（ListByStatus 全量孤儿，事件遗漏兜底）；逐项经 CloudAPIChannel.CleanupOrphanCert 路由 per 云 CloudDeployer.CleanupOrphan（幂等），结果 OrphanCleanupResult{cloud,cloudCertId,action,success,at} 经 OrphanCleanupRecorder 端口写入变更报告，失败项保留 orphan + AlertCategoryOps 运维处置告警（不计入 PRD 四类业务告警）；Hard Rule 三重门槛：清理前复核映射仍 orphan（被重新激活即未替换完成）、归属单活跃（activeMutex token / ListByNewCertID 任一在途即跳过）、保护期内 skip_keep 暂留；清理成功映射删除（status enum 仅 active/orphan，"标 cleaned"以删除承载）。(2) CrdRecheckService——RunDueRechecks 消费到期复检项（patch_crd 且 success 且 executedAt+recheckDelayMinutes<=now 且 recheckedAt 缺失），期望终态经 K8sAPIChannel.ResolveCloudCertID 同口径解析（patch 写入值与复检期望一致），调 5.6 RecheckCRDField 单轮复检：通过→项保持 success 仅固化 recheckedAt；回写/读取失败→项转 failed+error+TLS 差异通道告警（附 orderId/itemId）；复检次数固定 1（recheckedAt 幂等标记 + MarkRechecked CAS，失败不自动二次复检转人工）。幂等（AC-4）：孤儿清理以 recorder (orderID,cloudCertId,action,success) 去重 + 成功即删映射；复检以 recheckedAt 扫描排除 + CAS 落败跳过告警。配套：ChangeItem 新增 recheckedAt 字段（schema.sql/校验器/模型一致性测试同步）、CloudCertMappingRepository.ListByStatus/DeleteByID、ChangeOrderRepository.ListByNewCertID、ChangeItemRepository.ListPatchCRDDueRecheck/MarkRechecked 仓储原语及 certtest 共享 fake 实现。
