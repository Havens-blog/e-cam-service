### Key Decisions
- 角色集合语义替代单角色：双持 cert:manage+cert:settings 或 is_admin 的会话同时映射工程师+主管两角色（单角色模型下管理员必丢一面权限，与前端 isAdmin=全量口径冲突）；RequireRoles 改交集判定，SetRole 单值写入向后兼容全部既有测试
- viewer 默认开放仅限已认证会话：resolveCertRoles 空 claims 返回 nil（deny），有用户名等信号无 cert 码才映射 viewer——避免未认证流量经角色面放行
- 审计流单集合多投影：orphan_cleanup/verify 事件的报告存档载荷（Cloud/CloudCertID/Success/UnmetDomains）与审计正文同文档存储，避免 5.9/5.10 报告存档另开集合（新增 cert 集合需 schema.sql+validators+models_test 四处同步，成本不成比例）
- 去重唯一索引用 partialFilterExpression 而非 sparse：真实实例实测复合稀疏索引因 order_id/action 恒存在把 DedupKey 缺失文档以 null 键入索引，普通事件（如二次 create 审计）被误判重复；部分索引精确限定去重域（同 cert repository partialIndex 口径）
- GET /certs/:id 对 viewer 开放：任务 AC 只读查看者=dashboard+详情只读 与 6.1 前端路由守卫事实契约（viewer 可达 /certs/:id）一致，覆盖 api-handbook 原工程师/主管口径并同步修订 Auth 列；GET /changes 与 /:id 增审计角色同理（AC 运维主管/审计=+变更查看，PRD Story 5 审计阅变更报告），5.11 旧测试 TestChangeList_Roles 断言随契约演进更新
- 审计写入分层：订单生命周期人工事件在 handler 层记（actor=operator 可得）、系统事件（item_result/verify/orphan_cleanup/回滚结果）在 service 层经端口记（actor 从 ctx 取操作者、缺省 executor/scheduler 标识）——避免为 actor 改动 5.x 已冻结的服务签名
- 5.2 cancel 落 action=cancel（契约 action 清单为覆盖非穷尽，AC 明确要求 cancel 全量审计）；rollback 端点 handler 不重复记（5.8 RollbackAuditRecorder 六类 Outcome 事件更完整，避免双写）
- audit_test.go 全局中间件补测（multipart 占位/JSON 脱敏/cert 操作标签）——7.2 将全局审计定位为 cert HTTP 面全量审计载体，其私钥防护行为需测试锚定
