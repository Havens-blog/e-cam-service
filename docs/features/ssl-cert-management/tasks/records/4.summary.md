### 2. Key Decisions
- [4.1] 多证书同域名归属语义固定为「online 指纹匹配任一 owning 台账证书 = consistent」（Implementation Notes 选项）：换证共存期不误报 diff；TestProbe_MultiCertOwnershipSameDomain 钉死行为
- [4.1] change_linked_diff 判定新增 ChangeOrderRepository.ListVerifyingActive(ctx, after)（status=verifying AND verifyWindowUntil>after，createdAt 升序）——spec AC + tech-design 判定流程优先于「两新文件」note；additive 不破坏既有实现者
- [4.1] 通配符带 concreteSubdomainOverride 时：单结果记于 override 子域名按常规判定，不为被覆盖 SAN 另写 wildcard_skipped（避免看板 wildcardSkippedCount 双计缺口）；豁免判定仅在成功拨号时落定，拨号失败保持 unreachable（不可达不触发差异告警）
- [4.1] tlsDialer 接口缝：生产 stdTLSDialer（真实 crypto/tls、SNI ServerName、deadline 有界握手）经 addrOverride 直接对本地 SNI server 测试
- [4.2] 档位标签按降序阈值序号映射（最缓档→L30、次档→L14、第 3 档起折叠 L7）：schema expiryLevels 允许 5 项而枚举仅 3 个非过期标签，单调折叠保升级去重不变式
- [4.2] 升级路径先 PublishAlert 后 UpdateExpiryAlertLevel：发布失败不落状态、下轮重发（at-least-once）；去重状态持久化于文档字段而非内存（跨重启不重复告警有测试）；thresholds 经 AlertConfigRepository.Get 单文档 _id=global，空/非法回退 schema.sql DEFAULT [30,14,7]；notAfter 零值证书跳过不误报 expired

### 4. Conventions Established
- 告警依赖单向：cert 模块只定义 CertAlertEvent+CertAlertPublisher 接口，internal/alert 提供实现（alert→cert，cert 永不反向 import alert）；ioc 装配/调度注册统一顺延 7.1（同 Phase 2/3 生产装配顺延先例）
- payload 白名单=固定结构体（无 map 透传，测试断言实际 JSON 键集 ⊆ 白名单）；私钥/凭证/URL token 不得进入 payload、邮件正文、错误信息与投递记录；网络错误仅保留内层错误、状态错误仅保留状态码
- 四类业务告警（expiry/tls_diff/change_linked/rollback_failed）之外以 AlertCategoryOps 承载运维处置类（不计业务四类口径）；四类中仅到期分级跨巡检去重，其余按探测/事件逐轮触发
- at-least-once 语义：升级路径先发布后落去重状态，发布失败下轮重发；投递终态记录（sent/failed+原因）直写 ecam_alert_event，不入 pending 队列（防旧处理器误消费）
- 探测三不原则：只握手不发应用层请求、单域失败不中断整轮、超时/并发以常量边界（probeDialTimeout=5s/probeConcurrency=8）
- 看板口径单一来源：三个 rate 字段复用 LedgerService.Stats 不另算；dashboard/settings 响应白名单无私钥/凭据字段
- 消费侧端口+内存默认实现模式（InspectionRunStore↔service.LastInspectionSource 编译期断言）：生产持久化随 7.1 替换零改动；新增仓储接口方法须同步补 certtest fake
- 鉴权 deny-by-default：RequireRoles 门卫+CtxRoleKey 上下文键（7.2 EIAM 接线前测试经 SetRole 注入）；settings 面限运维主管/审计、dashboard 全角色走全局认证链

### 5. Deviations from Design
- **[4.1] 仓储方法增量（SPEC 优先级裁决）**：任务 note 称 probe 仅交付两新文件，change_linked_diff 判定实际需要 ChangeOrderRepository.ListVerifyingActive —— spec AC + tech-design「验证窗口告警路由」判定流程优先，additive 落地不破坏既有实现者
- **[4.3] ioc 装配顺延 7.1**：cert 模块尚无 ioc 文件，本任务提供 LoadCertSMTPConfig() 使装配零成本（同 Phase 2/3 生产装配顺延先例）；CertAlertEvent.VerifyWindow 为唯一既有文件增量
- **[4.3] 投递记录终态直写（实现细化）**：AC 口径「终态记录供补发/查询」落地为直写 sent/failed 而非 pending——既有 GetPendingEvents 按 status=pending 拾取，pending 记录会被旧处理器误消费
- **[4.4] InspectionRunStore 端口+内存默认实现（设计缺口补齐）**：tech-design 仅要求记录 lastInspectionAt 供 dashboard，schema.sql 无巡检运行集合并列且任务文件限定交付 Job 文件 → 不擅自新增集合，端口化留 7.1 持久化替换（同 Phase 2 D-2/Phase 3 namespace-kind 补齐先例）
- **[4.5] 服务端界值校验落地**：domain.ValidateThresholds 与 schema.sql minimum/maximum 1:1，修正原 Go 层「不校验」注释（越界 400 整体拒绝不部分写入有专项测试）；审计写入按任务边界留 7.2（豁免 operator 已持久化留痕）
- **[4.x] 环境限制（同 Phase 1/2/3 记录）**：-race 未执行（本机 CGO 禁用）、golangci-lint 未安装（Makefile lint 目标自身跳过）；go build/go vet/gofmt 全清
- **5.10 接口预留（设计内，非偏离）**：ProbeDomains 单轮入口、ProbeService 与 verifyWindowRoute 路由判定入参化（VerifyWindow.Active 入参）均为 5.10 验证窗口提频预留
- 其余无偏离：六态判定、通配符 concreteSubdomainOverride 处置、豁免仍探测不告警、expiryAlertLevel 升级去重状态机、告警四类 category 路由、RunInspection 天级节奏归 7.1、countsByLevel[5] 口径、crds 409/400、settings/test channelConfirmed 门控均与 tech-design.md 及 api-handbook 一致
