### Key Decisions
- Chain completeness requires a verifiable path from leaf to a self-signed anchor inside the uploaded bundle (self-signed leaf counts as complete); leaf-only or missing-intermediate bundles are rejected as CERT_CHAIN_INCOMPLETE per AC reading of 'self-signed root or given chain verifiable'
- Validity is checked explicitly before chain building, and chain verification uses the leaf validity midpoint as clock so expiry (CERT_PARSE_FAIL) and chain incompleteness (CERT_CHAIN_INCOMPLETE) never mask each other
- SAN structure rule: leaf with neither DNS SAN nor CN is CERT_PARSE_FAIL; malformed SAN extension fails at x509 parse; IP SANs are parsed but excluded from the domain SAN list per Implementation Notes
- Hard Rule zeroing: the function zeroes its own DER copy of the private key after comparison via domain.Zeroize; caller-owned keyPEM buffer is never mutated because task 2.2 must encrypt it after validation - contract documented on ParseCertAndKey and pinned by TestParseCertAndKeyDoesNotMutateInputs
- keyAlgorithm enum restricted to RSA|ECDSA (schema enum); other algorithms (e.g. Ed25519) are rejected as CERT_PARSE_FAIL
