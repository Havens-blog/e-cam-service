# 3.2: cloudx 腾讯云证书 API（同五方法，CDN/EdgeOne WAF/CLB）

## Description
扩展 `internal/shared/cloudx/tencent`：实现与 3.1 对称的证书五方法，覆盖腾讯云 CDN/EdgeOne(WAF)/CLB 产品。纯云 SDK 适配层，additive，接口形状与阿里云适配对齐（供 5.3 CloudAPIChannel 以统一 CloudDeployer 接口消费）。

## Reference Files
- docs/features/ssl-cert-management/design/tech-design.md — Interfaces / Interface 2: CloudDeployer（per 云 per 产品）、Error Handling / Error Types & Codes
- docs/features/ssl-cert-management/design/schema.sql: cert_references product 枚举（tencent: cdn/waf(EdgeOne)/clb） (ref: Interface 2: CloudDeployer（per 云 per 产品）)
- docs/features/ssl-cert-management/design/tech-design.md: 首期 6 产品×2 云 deployer 矩阵 (ref: Interfaces)

## Acceptance Criteria
- [ ] `internal/shared/cloudx/tencent` 新增证书适配：UploadCert/BindResource/ListReferences/GetCert/CleanupOrphan 五方法，签名与 3.1 阿里云适配同构（ creds + product 参数化）。
- [ ] 产品覆盖：cdn/waf(EdgeOne)/clb；product 枚举映射到腾讯云 SSL 证书 + 各产品域名/实例绑定 API。
- [ ] 凭证复用既有 tencent client/账号体系；限流错误 → `ErrCloudRateLimited` sentinel（与 3.1 同一错误定义，位于 cloudx 公共层）。
- [ ] GetCert 返回 CloudCertInfo{Exists,NotAfter,Fingerprint}（回滚有效性三判定数据源）。
- [ ] mock SDK 单元测试：五方法成功/限流/分页路径；不依赖真实云账号。
- [ ] `go build ./internal/shared/cloudx/...` 全绿，additive 不破坏既有接口。

## Hard Rules
- Additive only：新代码放新文件，不修改 tencent 既有适配签名。
- 与 3.1 的方法签名保持结构一致（差异仅 SDK 类型），便于 5.3 统一抽象。

## User Stories
Story 2（查看证书引用关系 — 腾讯云引用发现）、Story 3（一键批量更换 — 腾讯云两段式执行）。

## Implementation Notes
- 新增：`internal/shared/cloudx/tencent/cert.go`、`cert_cdn.go`、`cert_edgeone.go`、`cert_clb.go` + `*_test.go`。
- 腾讯云 SSL 证书（ssl）+ CDN 域名证书绑定 + EdgeOne + CLB 监听器证书 API；SDK 沿用仓库现有 tencent 依赖。
- 若某产品 API 能力受限（如 EdgeOne 证书绑定粒度差异），在代码注释与 5.12 PoC 记录中登记，不做静默降级。
