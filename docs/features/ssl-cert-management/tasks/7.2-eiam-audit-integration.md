# 7.2: EIAM 权限资源同步与审计接入（三角色资源声明、操作全量审计、审计按单查询口径）

## Description
证书功能域接入 EIAM 三角色权限资源（运维工程师=读写、运维主管/审计=审计+配置、只读查看者=看板只读）并启动期同步；变更/配置/豁免/CRD 全量操作经 internal/audit 记录（仅追加不可修改）；`GET /api/v1/certs/changes/:id/audit` 按变更单号查询审计流水，可与 ChangeReport 逐条比对一致（Story 5 AC）。

## Acceptance Criteria
- [ ] EIAM 权限资源声明：cert 全部端点的资源/动作映射三角色——运维工程师读写 cert 台账/引用/变更执行确认；运维主管/审计审计+配置（settings/exemptions/crds/test）+变更查看；只读查看者仅 dashboard+详情只读；启动期同步机制沿用现有（参考 internal/iam/EIAM 同步）。
- [ ] 鉴权拦截：角色不足 → 403 FORBIDDEN（web 层统一映射）；前端只读拦截已在 6.1，本任务保证后端接口侧拦截一致。
- [ ] 全量审计：cert 操作（cert 导入/删除/补传私钥、scan、change create/confirm/execute/confirm-batch/cancel、item_result、rollback、verify、orphan_cleanup、settings/exemptions/crds 增删改、settings/test）经 internal/audit 追加记录，含 actor/时间/操作对象/结果，不可修改。
- [ ] `GET /api/v1/certs/changes/:id/audit` 响应 `{logs[]{at,actor,action,detail,itemId?}}`，action 覆盖 create/confirm/execute/item_result/rollback/verify/orphan_cleanup，与 ChangeReport 逐条可比对一致（5.11 已定义端点契约，本任务实现审计写入+查询落地）。
- [ ] 测试：角色权限矩阵（三角色×关键端点的 200/403）、审计记录在典型操作后存在且字段完整、按单查询返回顺序与报告项一致。
- [ ] `go build ./...` 与既有 audit/iam 测试回归通过（additive 接入）。

## Hard Rules
- 审计记录仅追加、不可修改、不可删除（口径校验：无任何 update/delete 审计的代码路径）。
- 权限拦截必须后端接口侧强制（前端拦截仅为体验层，不得作为唯一防线）。

## User Stories
Story 5（审计与告警配置 — 报告与审计逐条比对一致 AC）、Story 6（只读查看者权限范围 AC）。

## Implementation Notes
- 修改/新增：
  - cert 域 EIAM 资源声明（沿用现有 internal/iam 同步机制——资源清单常量+启动同步调用），位置按现有 EIAM 资源声明约定（如 internal/iam 或 ioc 启动钩子）。
  - 各 cert service 在操作完成点调用 internal/audit 记录接口（参考 internal/cam 现有审计调用方式）。
  - `internal/cert/web/audit_handler.go`（GET /api/v1/certs/changes/:id/audit，查询经 internal/audit 按订单号过滤）+ 测试。
- 豁免/CRD/settings 变更的审计在 4.5 handler 内调用审计接口（本任务接线，若 4.5 已留 hook 则补全）。
