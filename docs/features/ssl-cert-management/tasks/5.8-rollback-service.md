# 5.8: 回滚服务（GetCert 目标有效性三判定、仅成功项、rollback_failed 项级状态、ROLLBACK_TARGET_INVALID 转人工）

## Description
ChangeService.Rollback：回滚对象仅限本次变更执行成功项（status=success）；逐项前置 GetCert(oldCloudCertId) 三判定（云侧已删除/已过期/指纹被替换 → ROLLBACK_TARGET_INVALID 转人工）；回滚将引用恢复为旧证书 ID，失败项标 rollback_failed + 立即告警转人工；订单收敛 rolled_back / rollback_failed。

## Acceptance Criteria
- [ ] Rollback(orderId, itemIds)：仅接受 status=success 的项（失败/skipped 项引用未被改动不参与回滚，仅在报告标记）；入口状态=执行中（出现失败项后）/验证中/部分完成。
- [ ] 前置三判定（GetCert(oldCloudCertId)）：Exists=false（云侧已删除）、NotAfter < now（已过期）、Fingerprint ≠ 订单 oldCertFingerprint（被替换）→ 该项 ROLLBACK_TARGET_INVALID：不自动回滚、转人工决策、记录审计。
- [ ] 回滚执行：经通道 Rollback 恢复引用为旧证书 ID；成功 → 项标 rolled_back；失败 → rollback_failed + 立即告警（四类中"回滚失败"）转人工；K8s 项按 patch 恢复旧值。
- [ ] 订单收敛：全部成功项回滚成功 → rolled_back；任一 rollback_failed → rollback_failed（终态转人工）。
- [ ] 回滚过程产生孤儿云证书同步清理（RollbackResult.OrphanCleaned）记录入报告。
- [ ] 集成测试（mock 通道）：三判定各分支、仅成功项范围约束、部分回滚失败→rollback_failed、订单状态收敛。

## Hard Rules
- 失败项绝不自动回滚（其引用从未被改动）；无效目标绝不自动回滚（转人工+审计）。
- 回滚自身失败必须立即告警（第四类）不得静默。

## User Stories
Story 3（一键批量更换 — 回滚语义全部 AC）、Story 5（报告含回滚状态）。
