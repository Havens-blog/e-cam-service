# 1.1: 信封加密组件（AES-256-GCM、keyVersion 轮换、双读、zeroing）

## Description
新增 `internal/cert` 功能域的信封加密基座：AES-256-GCM 对称加密私钥与 kubeconfig 等敏感载荷。主密钥按 `keyVersion` 版本化，支持轮换双读；解密后的明文仅存内存、用后 zeroing，禁入日志/响应/审计。该组件被 1.2 仓储层、3.4 K8s 凭证、5.3 Credential 解密等复用。

## Acceptance Criteria
- [ ] `Encrypt(plaintext []byte) (ciphertext string, keyVersion int, err error)` 使用 AES-256-GCM，nonce 随机、每次密文不同；输出 base64。
- [ ] `Decrypt(ciphertext string, keyVersion int) ([]byte, error)` 按版本路由到对应主密钥；双读支持：env 可同时驻留多个版本，写路径固定用最新版本。
- [ ] 篡改密文 → GCM 认证失败返回显式错误（不 panic、不返回部分明文）；未知 keyVersion → 显式错误。
- [ ] 主密钥从环境变量注入，独立于业务数据；启动期缺失必需版本 → 启动失败（fail-fast）。
- [ ] `Zeroize(b *[]byte)`/`defer Zeroize`：解密明文用后置零；私钥/凭证片段不出现在任何日志、错误 message、响应体。
- [ ] 表驱动单元测试：轮换双版本并存、双读解密、篡改/截断密文、轮换迁移模拟（旧版密文→新版再加密）。

## Hard Rules
- 永不返回明文私钥/凭证片段（任何函数签名、日志、错误、审计均不得携带）。
- 明文 `[]byte` 用后必须 zeroing；禁止将明文存入可逃逸作用域（闭包捕获后未释放、序列化为 string 等）。
- 主密钥不得落库；仅 env 注入，迁移期不下线旧版主密钥。

## User Stories
Story 1（加密存储私钥）— 间接支撑（导入校验/托管的底层加密能力）。

## Implementation Notes
- 新增 `internal/cert/domain/crypto.go` + `internal/cert/domain/crypto_test.go`。
- 主密钥 env 约定：`EIAM_CERT_MASTER_KEY_V1`、`EIAM_CERT_MASTER_KEY_V2`…（双版本并存）；版本号由 env 后缀解析，写路径取最大已配置版本。
- `algo` 固定 `AES-256-GCM`，与 schema.sql enum 一致。
- 复用 Go 标准库 `crypto/aes` + `crypto/cipher` (GCM) + `crypto/rand`，不引入第三方加密库。
- 测试用临时生成的 32 字节主密钥，不依赖真实 env。
