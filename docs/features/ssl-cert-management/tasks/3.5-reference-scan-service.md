# 3.5: 引用扫描服务（五云+K8s 快照扫描、coverageMeta 分母=asset 盘点固化、referenceStatus 三态、scan-timeout 恢复、防重）

## Description
引用发现编排：单次扫描创建 ScanSnapshot（running），经 cloudx 五云适配 + K8s dynamic client（固定枚举+登记 CRD）发现 CertReference（含 namespace/kind，写 snapshotId/scannedAt），coverageMeta 分母从 internal/asset 资产盘点按 Provider×产品聚合固化（不可用→-1），完成转 done；防重（running → 409 SCAN_IN_PROGRESS）与 scan-timeout 恢复函数（running 超时转 failed 释放锁）。调度注册在 7.1。

## Acceptance Criteria
- [ ] 扫描启动：创建 ScanSnapshot{startedAt, status=running}；已有 running 快照 → 409 SCAN_IN_PROGRESS（防重）。
- [ ] 五云+K8s 发现：逐云逐产品调 ListReferences（3.1/3.2/3.3）；K8s 按固定枚举+enabled 登记遍历、按 certFieldPath 读引用字段；发现的 CertReference 写 certFingerprint（由 referencedCloudCertId 经映射/证书要素匹配解析，无法解析时保留引用并以云证书 ID 关联）、snapshotId、scannedAt；K8s 引用含 clusterId/namespace/kind。
- [ ] coverageMeta 固化：扫描启动时按云×产品聚合 internal/asset 在用资源计数为 total；asset 不可用或计数异常（0 但历史非 0）→ total=-1；covered=本轮 CertReference 去重资源数；covered>total 时以 covered 为准并标记滞后。
- [ ] 终态：全部成功 → status=done + finishedAt；某通道失败 → 该云/产品记入快照元数据（部分失败不阻塞其他云），整体失败 → failed + failReason。
- [ ] scan-timeout 恢复函数 `RecoverTimedOutScans()`：running 且 now > startedAt + scanTimeoutHours → failed（failReason=SCAN_TIMED_OUT）+ 告警事件 + 释放防重锁（可重新触发）。
- [ ] 集成测试（mock 五云+fake K8s）：快照生命周期、coverageMeta 分母口径与 -1 分支、防重 409、超时恢复、K8s 引用字段（namespace/kind）落库。

## Hard Rules
- 扫描为只读操作：不触发任何云侧写 API（discovery-only 约束同样适用于 aliyun/tencent 的发现面）。
- coverageMeta.total 必须来自 internal/asset 聚合，不得用扫描自身发现的资源数当分母（防自指）。

## User Stories
Story 2（查看证书引用关系 — 扫描与覆盖率元数据）、Story 3（换证前置：扫描新鲜度基准）。
