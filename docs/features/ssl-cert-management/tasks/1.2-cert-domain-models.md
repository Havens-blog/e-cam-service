# 1.2: 领域模型与仓储层（12 模型 + repository 接口与 Mongo 实现 + 集合初始化与索引）

## Description
落地 `internal/cert` 的领域模型与持久化层，对齐 schema.sql 的 12 个集合：Certificate/CertReference/ScanSnapshot/ChangeOrder/ChangeItem/CloudCertMapping/ProbeResult/Exemption/AlertConfig/K8sCredential/CertBatchSession/CrdRegistration。领域层定义模型与 repository 接口，repository 子包提供 Mongo 实现，module init 注册集合校验器与全部索引（唯一/部分唯一/TTL）。

## Reference Files
- docs/features/ssl-cert-management/design/tech-design.md — Data Models / Field Quick Reference、在途互斥的并发强制（activeMutex token）、覆盖率分母
- docs/features/ssl-cert-management/design/schema.sql: 全部 createCollection/$jsonSchema/createIndex (ref: Field Quick Reference)
- docs/features/ssl-cert-management/design/er-diagram.md: 11 集合关系与索引策略 (ref: Data Models)

## Acceptance Criteria
- [ ] 12 个模型定义于 `internal/cert/domain`，字段名/bson tag 与 schema.sql camelCase 完全一致；枚举值（hostingStatus/status/probeStatus/expiryAlertLevel 等）对齐。
- [ ] repository 接口定义于 domain 子包，Mongo 实现于 `internal/cert/repository`，按 e-cam 现有 mongox 约定（参考 internal/cam/repository）。
- [ ] `EnsureIndexes(ctx)` 在 module init 执行 schema.sql 全部索引：含 `uk_active_mutex` 部分唯一索引、`uk_fingerprint`、`uk_fp_cloud_account`、`uk_cluster_group_kind`、`ttl_probe_90d`、`ttl_batch_session_30d`、`idx_status_heartbeat`（partial status=running）。
- [ ] Certificate 按 fingerprint 唯一：upsert 冲突 → 返回 sentinel `ErrDuplicateFingerprint`（供 2.2 映射 409）。
- [ ] activeMutex 原子迁移封装：进入活跃态 `Set activeMutex=token`、终态同原子 update `$unset`（提供 repository 层 helper，状态机逻辑在 5.1）。
- [ ] repository 集成测试用 mongox test 实例：集合校验器拒绝越界文档（如 hostingStatus 非法值、fingerprint 非 64 hex）、部分唯一索引在并发双 insert 抛 duplicate key。

## Hard Rules
- 模型/索引必须与 schema.sql 字段名、enum、索引定义 1:1 对齐，不得自行增删字段。
- `encryptedPrivateKey`/`kubeconfig` 在模型层为密文形态（{ciphertext,keyVersion,algo}），明文不入模型；repository 不得有返回明文的方法。

## User Stories
间接支撑 Story 1-6（全部数据承载层）。

## Implementation Notes
- 新增目录结构：
  - `internal/cert/domain/certificate.go`、`cert_reference.go`、`scan_snapshot.go`、`change_order.go`、`change_item.go`、`cloud_cert_mapping.go`、`probe_result.go`、`exemption.go`、`alert_config.go`、`k8s_credential.go`、`batch_session.go`、`crd_registration.go`、`repository.go`（接口聚合）。
  - `internal/cert/repository/*.go`（每集合一个实现文件）、`internal/cert/repository/indexes.go`（EnsureIndexes）。
- repository 接口风格参考 `internal/cam/repository`（按集合拆分 + dao 子包可选拟同）。
- 仅依赖 1.1 的 crypto helper 处理加密字段（不在本任务做业务加解密逻辑，仅承载密文形态）。
- 测试：复用 e-cam 现有 mongox test 启动方式；运行 `go test ./internal/cert/...`。
