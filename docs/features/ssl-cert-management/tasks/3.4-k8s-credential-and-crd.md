# 3.4: K8s 凭证管理与 CRD 登记（kubeconfig 加密存取、client-go dynamic client、CRD 登记表 CRUD、内置默认登记）

## Description
K8s 接入基座：K8sCredential（kubeconfig 经 1.1 信封加密存取、clusterName 唯一）、基于 client-go 的 dynamic client 工厂（CRD 通用 list/get/patch）、CrdRegistration 登记 CRUD（clusterId+apiGroup+kind 唯一、certFieldPath 校验、enabled 开关）与内置默认登记（ALBConfig/Ingress/Gateway/HTTPRoute）���本任务交付 service 层；HTTP 端点（/settings/crds）在 4.5 落地。

## Acceptance Criteria
- [ ] K8sCredential 服务：新增/列表/删除集群凭证；kubeconfig 加密落库（AES-256-GCM + keyVersion），任何读取路径不返回明文（仅 clusterName/apiEndpoint/createdAt）。
- [ ] dynamic client 工厂：按 clusterName 解密 kubeconfig → 构建 client-go dynamic client（缓存复用）；连接失败 → `ErrK8sUnreachable`（K8S_UNREACHABLE 语义）。
- [ ] CrdRegistration CRUD（service 层）：登记/列表/删除/启停；clusterId+apiGroup+kind 唯一冲突 → sentinel 供 4.5 映射 409；certFieldPath 语法校验（如 `spec.certificates[].certificateId`）。
- [ ] 内置默认登记：ALBConfig/Ingress/Gateway/HTTPRoute 四类固定枚举作为内置登记项（enabled=true，不可删除时给出明确错误或标记内置），随扫描范围生效。
- [ ] 登记限定：certFieldPath 非法（不可解析路径）在校验期拒绝或扫描时报错（含可读错误信息）。
- [ ] 单元测试：fake dynamic client（或 envtest）覆盖 list/get/patch 通路、kubeconfig 加解密存取、唯一冲突、默认登记初始化幂等。

## Hard Rules
- kubeconfig 明文仅内存解密用后 zeroing；禁入日志/响应/审计。
- client-go 为新增依赖：`go.mod` 引入 `k8s.io/client-go`（版本锚定兼容 K8s 1.24+，最终版本以 5.12 PoC/首批验证结论锁定，见 tech-design Open Questions）。
