# 6.5: 变更向导与管理组件（UF-4：7 步向导/阻断/分批/进度/验证窗口/报告详情/重入）

## Description
构建 UF-4 全部组件：变更管理列表页（状态 Tab/表格/10s 轮询/配置入口）、7 步变更向导（选择证书→前置校验→清单→确认执行→执行进度→验证窗口→报告）、变更报告详情页（5 卡报告 + 执行/验证中只读恢复视图 + 草稿续编 + 执行剩余批）。本任务是前端最重组件，覆盖全部阻断/门控/轮询/重入交互。

> 跨仓库任务：文件位于 e-cam-web 仓库，路径为仓库相对路径。

## Acceptance Criteria
- [ ] 列表页：状态 Tab 全集（待确认含草稿；已回滚/回滚失败合并 Tab 可按徽章区分）；列（单号/旧→新[旧侧保护期徽章]/状态徽章/进度/发起人/时间/操作）；执行中/验证中行 10s 轮询刷新；配置入口（仅主管）；空态"新建变更"CTA。
- [ ] 7 步向导：步骤条当前步高亮、已完成步只读回看（"只读回看"徽章+返回当前步骤）、未到达不可点；下一步闸门（Step1 双选/Step2 双预检过/Step3 清单生成/Step4 确认）；Step1-4 可存草稿、任意步取消二次确认；?certId= 预选旧证书（非完整托管/无引用时置空+提示，不锁选择器不跳步）。
- [ ] Step2 预检自动执行整步 loading；阻断卡（扫描超期→「立即扫描」引导 / SAN 不满足 / 在途互斥指向 CHG-XXXX 跳转 / 新证书仅指纹提示）；Step3 清单可执行项表格+不可执行项分区（Warning 底色+原因+出路）+盲区横幅+快照时间；Step3 生成失败可重试可返回。
- [ ] Step4 确认：影响面摘要 Modal 二次确认；分批勾选首批上限 floor(总量/2) 超限禁用；确认时服务端快照重校验失败 → Error"引用清单已变化，请重新预检"+自动回退 Step2。
- [ ] Step5 执行 2s 轮询逐项状态（成功✓/失败✗/执行中 spinner/限流重试中[Warning]）；出现失败项→顶部横幅+回滚成功项入口（Modal 含目标有效性预检与转人工提示）；Step6 验证窗口倒计时+逐项验证徽章+回滚入口+执行剩余批入口；Step5→6 全项终态自动进、Step6→7 窗口关闭自动进（达标可"提前完成"二次确认）。
- [ ] 报告详情页：5 卡（变更清单/逐项结果[批次+结果筛选]/回滚状态/验证结论[未达标清单+窗口结论]/孤儿清理）+导出+只读恢复视图（执行中内嵌 Step5/验证中内嵌 Step6，重入轮询自动恢复；部分完成[保护期内]回滚入口+保护期徽章；草稿/待确认"继续编辑"跳向导；执行剩余批人工确认）；高频轮询/倒计时 a11y 策略按 ui-design（跨小时档/终态事件才 aria-live；reduced-motion 倒计时隐藏秒位、进度条改静态文本）。

## Hard Rules
- 回滚入口仅 执行中(出现失败项后)/验证中/部分完成 三态可见，且仅作用于执行成功项。
- 确认操作仅运维工程师角色可见可用；全程操作调用留审计的服务端端点。
- 执行期间清单快照固定：前端不得提供执行中增删清单项的任何入口。

## User Stories
Story 3（一键批量更换 — 全部 AC 的前端承载）、Story 5（报告查看）。
