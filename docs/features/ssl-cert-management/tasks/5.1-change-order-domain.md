# 5.1: 变更单领域与状态机（9 态、activeMutex 部分唯一索引互斥、草稿/取消/CHANGE_NOT_CANCELLABLE、保护期字段）

## Description
变更单 ChangeOrder 的领域状态机与互斥层：9 态（draft/pending_confirm/executing/verifying/completed/partial_completed/rolled_back/rollback_failed/cancelled）合法迁移、activeMutex token 由 1.2 部分唯一索引在 DB 层强制（同 oldCertFingerprint 仅一张活跃单）、Cancel 语义（draft/pending_confirm/paused 整单取消、executing 中止、verifying/终态不可取消 → CHANGE_NOT_CANCELLABLE）、protectUntil 保护期字段设置。

## Acceptance Criteria
- [ ] 状态机迁移函数 `Transition(current, target) error`：合法迁移白名单（draft→pending_confirm→executing↔verifying→completed/partial_completed→rolled_back/rollback_failed；cancelled 终态来源见下）；非法迁移 → 错误。
- [ ] activeMutex：进入活跃态（pending_confirm/executing/verifying）写 activeMutex=oldCertFingerprint；终态（completed/partial_completed/rolled_back/rollback_failed/cancelled）在同一原子 update `$unset` token；冲突 insert → duplicate key 映射 sentinel `ErrChangeInFlight`（CHANGE_IN_FLIGHT）。
- [ ] Cancel：draft/pending_confirm/批间暂停（batchInfo.paused=true）→ cancelled（未执行项标 skipped，activeMutex 同原子清除）；executing → pending 项标 skipped、running 项不中断、待其完成后按剩余项重算收敛 cancelled；verifying 与终态 → 409 CHANGE_NOT_CANCELLABLE。
- [ ] protectUntil：进入 completed/partial_completed 时按 rollbackProtectDays 设 protectUntil；保护期内禁止删旧证书（2.3 已用该字段拦截）。
- [ ] 应用层预检查仅作快速失败，正确性由 activeMutex 部分唯一索引保证（check-then-insert 竞态窗口被关闭）。
- [ ] 领域测试：迁移矩阵、并发双 insert 仅一张活跃（用 mongox test 实例验证 duplicate key）、Cancel 各分支、CHANGE_NOT_CANCELLABLE。

## Hard Rules
- 互斥正确性必须由 DB 索引保证，不得仅靠应用层检查。
- 终态迁移与 token 清除必须同原子 update，防止终态单残留 token 阻塞新单。
