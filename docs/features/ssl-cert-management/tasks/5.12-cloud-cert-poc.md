# 5.12: 双云证书 API 能力 PoC 验证记录（真实账号验证 UploadCert/Bind/GetCert 限制与配额，输出结论到 design/poc-notes.md）

## Description
用真实阿里云/腾讯云账号对 3.1/3.2 实现的证书 API 做能力 PoC：逐产品验证 UploadCert/BindResource/GetCert 的可用性、限制（命名规则/证书格式/绑定粒度）与配额（证书库容量/上传频率/绑定数量），记录坑点与结论，输出 `design/poc-notes.md`，并回填 tech-design Open Questions 中双云 API 能力项。验证结论直接影响 5.4/5.5 的实现修正。

## Acceptance Criteria
- [ ] 阿里云真实账号验证：CDN/DCDN/WAF/ALB(NLB) 四类产品的 UploadCert→BindResource→GetCert→CleanupOrphan 全链路各至少一次成功，记录每步请求/响应要点（脱敏）。
- [ ] 腾讯云真实账号验证：CDN/EdgeOne(WAF)/CLB 三产品同上全链路验证。
- [ ] 限制与配额记录成表：证书命名/格式限制、证书库配额、上传频率限制、绑定粒度（如 CLB 监听器级）、限流阈值表现。
- [ ] 失败与限制场景记录：至少覆盖限流响应形态、格式拒绝、重复上传行为（幂等 or 报错）。
- [ ] `design/poc-notes.md` 产出且 tech-design Open Questions 对应项关闭；发现的代码偏差已回填 3.1/3.2（或登记为 5.4/5.5 修正项清单）。

## Hard Rules
- PoC 产生的测试证书/绑定必须在验证后清理（不留测试残留于生产云账号）。
- 记录中不得出现 AK/SK、私钥等敏感片段（请求样例脱敏）。
- 仅使用测试证书（现场生成自签/测试证书），不得动用生产在用证书。

## Implementation Notes
- 依托 3.1/3.2 已实现的适配代码驱动真实调用（可写临时 main/测试标签 `-tags=poc` 驱动，验证后删除驱动代码或保留在 test 标签内）。
- 验证环境用开发/测试云账号（与生产账号隔离）；连接信息经 env 注入。
- 若某产品能力缺失（如 EdgeOne 某绑定能力不可用），在 poc-notes 明确"该产品首期降级/移出部署器矩阵"的建议与影响面。
