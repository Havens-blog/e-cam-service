# 4.2: 到期分级告警引擎（30/14/7 分级计算、expiryAlertLevel 升级去重、四类告警事件发布）

## Description
InspectionService 核心：天级按 notAfter 计算 daysLeft 命中 thresholds.expiryLevels（默认 [30,14,7] 降序取最紧急级）或 expired 级；Certificate.expiryAlertLevel 持久化去重状态——仅升级触发告警，同级不重发，换证后重置 none；定义四类业务告警事件（到期分级/TLS 差异/变更关联/回滚失败）的统一发布接口，经 4.3 通道触达。

## Acceptance Criteria
- [ ] 分级计算：daysLeft = ceil((notAfter - now)/24h)；按 expiryLevels 降序匹配取最紧急命中级（30→L30、14→L14、7→L7）；已过期 → expired。
- [ ] 去重状态机：新级别较已触发级别更紧急（L30→L14→L7→expired 单向升级）→ 发告警并更新 expiryAlertLevel；同级/降级不重复触发；换证后（notAfter 回升出级别区间）重置 none 并重新计级。
- [ ] 告警事件模型 `CertAlertEvent{Category: expiry|tls_diff|change_linked|rollback_failed, ...}`：统一发布接口 `PublishAlert(ctx, event)`，由 4.3 通道实现消费（本任务定义接口 + 内存/日志默认实现）。
- [ ] 到期分级事件按证书粒度聚合内容（指纹/SAN 摘要/级别/daysLeft/到期时间），不含私钥。
- [ ] 单元测试：30→14→7→expired 逐级升级触发、同级别天级巡检重复执行不重发、换证重置后重新触发、levels 配置变化（如 [45,20]）正确计级。

## Hard Rules
- 去重状态必须持久化（expiryAlertLevel 字段），不得仅内存去重（服务重启不重复告警）。
- 四类告警类别区分以 category 字段承载，alert 通道不得把到期分级当差异类处理。

Story 5（审计与告警配置 — 到期事件触达全局接收人）、Story 6（到期看板分级数据）。
