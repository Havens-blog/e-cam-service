# 4.3: 告警通道扩展（internal/alert 复用扩展 webhook+email、verifyWindowRoute 窗口路由、发送失败退避）

## Description
复用 `internal/alert` 既有 channel 框架，扩展证书域告警触达：webhook + 邮件两通道；verifyWindowRoute 窗口路由（change_linked_diff 走变更关联专用通道，未启用复用常规通道+标记）；发送失败退避重试（有界）。Additive：不破坏 alert 模块既有接口与既有告警流。

## Reference Files
- docs/features/ssl-cert-management/design/tech-design.md — Architecture / Dependencies（internal/alert 复用+扩展）、验证窗口告警路由（change_linked_diff）
- docs/features/ssl-cert-management/design/schema.sql: cert_alert_config webhookUrls/emailGroup/verifyWindowRoute (ref: 验证窗口告警路由（change_linked_diff）)
- docs/features/ssl-cert-management/prd/prd-spec.md: 告警渠道 webhook+SMTP、渠道确认为验收门控 (ref: Architecture / Dependencies)

## Acceptance Criteria
- [ ] 证书域告警消费 4.2 `CertAlertEvent`：webhook（POST JSON，含 category/orderId/摘要）与 email 两组接收人按 AlertConfig 配置触达；运维处置类通知（孤儿清理失败/超时取消）可标记为非业务四类。
- [ ] verifyWindowRoute：enabled=true 时 change_linked_diff 事件走专用 webhookUrls/emailGroup（附 orderId、预期指纹、达标计数）；enabled=false 走常规通道但附变更关联标记；窗口关闭后恢复常规路由（由 5.10 控制，本任务支持路由判定入参）。
- [ ] 发送失败退避：按固定退避序列重试（有界次数），最终失败记录失败状态与原因，事件不丢失（保留事件记录供补发/查询）。
- [ ] Additive：`go build ./internal/alert/...` 与既有 alert 测试全绿；既有告警消费方行为不变。
- [ ] 测试：mock HTTP server（webhook 成功/失败/限流）+ mock SMTP；路由两分支；退避上限后不再无限重试。

## Hard Rules
- 告警内容不得含私钥/凭证片段；webhook payload 字段白名单。
- 退避重试必须有上限，禁止无限重试阻塞任务队列。

## User Stories
Story 5（审计与告警配置 — webhook+邮件触达全局接收人）。

## Implementation Notes
- 修改/扩展：`internal/alert/channel/`（新增证书域通道实现或适配器）、`internal/alert/service/`（消费 CertAlertEvent 的接线）；尽量以新增文件实现，对既有文件的改动最小化。
- SMTP 凭据来源沿用 alert 模块现有配置机制（tech-design Open Questions 中"凭据来源待配置"项，实现时以应用 config 注入并在缺省时启动警告而非失败）。
- 与 7.2 无重叠：本任务只做通道能力；EIAM/审计在 7.2。
