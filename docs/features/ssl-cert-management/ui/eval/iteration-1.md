## Phase 1 — 推理审计摘要

PRD 覆盖面总体良好：5 个 UI Function（UF-1~UF-5）均有对应组件；3 个一级导航入口齐全；只读角色拦截、盲区声明、在途互斥、分批 ≤50%、回滚语义等硬规则均已体现。但存在以下结构性缺口：

1. **"变更报告详情"次级页面没有组件定义**——PRD Navigation Architecture 明确列为 Secondary Page（入口"UF-4 变更管理列表行点击"），设计中仅以一句交互（"查看报告 | 报告详情页 | 面包屑返回列表"）和向导 Step7 内容带过，无路由、无布局、无状态表、无数据绑定，Page Composition 也未收录。
2. **变更管理列表页无状态定义**——States 表自我标注"States（向导关键态）"，PRD UF-4 要求的列表 loading/empty/error 三态全部缺失。
3. **两处孤儿元素**：台账页"批量导入"按钮（PRD 明确要求单张/批量导入）在 Interactions 与 Data Binding 两表中均无条目；详情页"关联变更历史列表"在绑定表中无法对应（"cert 全要素"不含变更历史，该数据应源变更服务）。
4. **UF-2 正向引用的"按云/产品/集群筛选、搜索资源名"交互缺失**——反向 Tab 有搜索框，正向只有分组折叠列表。

## Phase 2 — 四视角评分

### 1. Requirement Coverage（PM 视角）— 199 / 250

| 子项 | 得分 | 说明 |
|------|------|------|
| UI function coverage | 62 / 80 | 见下 |
| Navigation Architecture coverage | 28 / 40 | 见下 |
| State requirement coverage | 68 / 80 | 见下 |
| Edge case handling | 41 / 50 | 见下 |

**UI function coverage 扣分：**

- **-8 台账"批量导入"无流程定义**。PRD UF-1 要求"提供单张/批量导入"，设计布局中有 `[批量导入 Secondary]`、空态 CTA `"批量导入存量证书" Primary 按钮`，但 Interactions 表只有"导入证书"单张 Modal 的 7 条交互，批量导入的表单形态（多文件？目录？压缩包？）、校验失败呈现（逐文件错误？）、进度反馈全部未定义。这是 UF-1 的半个功能面。
- **-7 UF-2 正向引用筛选/搜索缺失**。PRD UF-2 交互流程第 2 步："用户按云/产品/集群筛选、搜索资源名"。设计的正向 Tab 仅 `"分组折叠列表: ▾ 阿里云 · DCDN (8)"`，无筛选控件、无资源名搜索框；搜索能力只出现在反向 Tab（`"Tab 反向：搜索框(域名/资源名)"`）。
- **-4 回滚保护期标记在台账行未体现**。PRD UF-4 流程第 7 步："回滚保护期内旧证书行显示保护期标记"。设计仅在变更列表状态（"部分完成 | 报告入口 + 成功项回滚入口 + 保护期剩余"）和删除拦截提示中涉及保护期，台账表格列（`域名/SAN │ 签发者 │ 有效期 │ 剩余 │ 托管状态 │ 引用数 │ 操作`）无任何保护期标记列/角标定义，PRD 要求落点不明。
- **-2 统计口径缺一**。PRD UF-1 统计概览要求三项："登记覆盖率、可更换托管覆盖率、仅指纹登记占比"；设计统计卡为 `"完整托管 (N) | 仅指纹登记 (N) | 覆盖率：登记 ≥90% 目标 / 可更换托管"`，仅指纹登记只有绝对数 N，无占比口径。

**Navigation Architecture coverage 扣分：**

- **-12 变更报告详情次级页面半覆盖**。PRD Secondary Pages 表要求"变更报告详情 | UF-4 变更管理列表行点击 | 返回变更管理"。设计中该页面无 Placement/Target 路由、无 Layout、无 States、无 Data Binding，Page Composition 六页中不含它；仅向导 Step7 内容（`Step7 变更报告: 清单/逐项结果/回滚状态/验证结论/孤儿证书补偿清理结果(逐项清理成功/失败) + 导出`）和一条交互（`查看报告 | 报告详情页 | 面包屑返回列表`）可视为部分素材。历史变更单的报告查看路径对开发者而言是空洞。
- **-8 列表行点击入口缺失 + 向导返回导航未定义**。PRD 入口定义为"变更管理列表行点击"，设计布局操作列只有 `│ 详情 │`，无行点击行为；同时 PRD Navigation Rules 要求"Every secondary page has back navigation targeting its entry point page"，向导页（从台账"发起更换"进入）的上一步/取消/返回目标完全未定义。

**State requirement coverage 扣分：**

- **-12 变更管理列表三态缺失**。PRD UF-4 States 表明确要求 `loading（列表/清单/报告首次加载）、empty（空态引导"新建变更"入口）、error（变更服务异常）`；设计 States 表标题即为 `"States（向导关键态）"`，七个状态全部是向导/执行态，列表页 loading/empty/error 一概没有。

**Edge case handling 扣分：**

- **-4 长文本溢出未处理**。SAN 列表（`SAN 列表(mono chips)`）与表格列"域名/SAN"面对多 SAN 证书（几十个 SAN 常见）无截断/折叠/tooltip 规则；变更列表"旧证书→新证书"列同理。
- **-3 /certs/settings 越权直达未定义**。设计对只读角色定义了 `/certs 与 /certs/changes 路由前端拦截提示无权限`，但配置页仅写"仅运维主管/审计角色可见"，普通工程师直达 /certs/settings 的拦截行为未说明。
- 正向项：删除拦截、在途互斥、扫描超期、回滚失败转人工、"未发现引用 ≠ 无引用"、800ms 骨架直渲等边界均已覆盖，予以认可。

### 2. User Experience（终端用户视角）— 203 / 250

| 子项 | 得分 | 说明 |
|------|------|------|
| Information hierarchy | 74 / 80 | |
| Interaction intuitiveness | 73 / 80 | |
| Accessibility | 56 / 90 | 本设计最弱项 |

**Information hierarchy 扣分：**

- **-3 覆盖率卡信息过载**。`覆盖率：登记 ≥90% 目标 / 可更换托管` 一张卡塞入两个口径加一个目标值，且"≥90% 目标"是管理目标而非当前值，用户无法一眼分清"现状 vs 目标"。
- **-3 高危操作藏于 ⋯ 菜单**。`⋯ 菜单（删除、补传私钥[仅指纹登记行]）`——删除是台账页核心高频决策操作，与"详情/发起更换"平级列出的信息架构里被折叠进二级菜单，与全局模式"危险操作 Modal 二次确认"的重防护定位不匹配。

**Interaction intuitiveness 扣分：**

- **-5 向导步间导航未定义**。布局仅有"分步，顶部步骤条"，交互表中唯一出现的导航是阻断态的 `"上一步"或"立即扫描"`。用户如何从 Step1 前进到 Step2、步骤条可否点击跳转、能否中途取消，均无从得知——7 步向导的骨架有、关节没有。
- **-2 反向查询仅"回车"触发**。`反向查询搜索 | 输入域名/资源名回车`——无按钮、无即时反馈、无空查询处理说明，输入框是否支持清空/防抖未定义。

**Accessibility 扣分（无障碍章节整体缺失）：**

- **-12 无键盘导航与焦点管理规范**。全文无一处键盘操作定义：Modal/Drawer 的焦点陷阱、Esc 关闭、Tab 顺序全部空白（`Drawer z30`、`Modal z30` 只给了层级，没给焦点行为）。
- **-8 状态传达未承诺非色觉通道**。`剩余天数(状态色徽章)` 有文字可读，但 `差异行 | 行内 Error 角标 + 最近探测时间 tooltip` 的"角标"是否伴随文本未说明；`执行进度: 逐项状态行(成功✓/失败✗/…)` 依赖 ✓/✗ 符号尚可，但角标类纯视觉标记对色觉障碍用户存在风险。
- **-6 无表单标签规范**。`webhook URL 输入(mono) + 邮件接收组(tag 输入)` 等控件全文只描述控件类型，无 label/placeholder/错误提示关联（aria）要求。
- **-4 无动效偏好处理**。`150ms 过渡`、`分组折叠/展开 手风琴 150ms 过渡` 未提及 prefers-reduced-motion。
- **-4 对比度未验证**。`Text Secondary #888888` 置于 `Surface Alt #171717`（表头/hover 行）上对比度约 3.9:1，低于 AA 正文标准；文档未声明任何对比度校验。

### 3. Design Integrity（设计师视角）— 208 / 250

| 子项 | 得分 | 说明 |
|------|------|------|
| Design system adherence | 72 / 80 | |
| Visual coherence | 81 / 90 | |
| State completeness | 55 / 80 | |

**Design system adherence 扣分：**

- **-8 调色板外引入 #8b5cf6**。Color Palette 表共 11 色并无紫色；全局模式却写 `验证中=#8b5cf6（紫，仅此一处）`。"仅此一处"本身承认了这是对系统的逃逸——Vercel 单色体系里凭空多一个状态色，且未列入色板表，实现者容易漏配 token。

**Visual coherence 扣分：**

- **-4 操作命名不一致**。变更列表布局图操作列为 `│ 详情 │`，交互表却写 `查看报告 | 报告详情页`——同一入口两处两个名字。
- **-5 状态 Tab 集合与状态机全集不一致**。状态徽章映射覆盖八态（草稿/待确认/执行中/验证中/已完成/部分完成/已回滚/回滚失败），列表 Tab 却只有 `全部 | 执行中 | 验证中 | 部分完成 | 已完成`——"已回滚/回滚失败/待确认"三类单据只能靠"全部"翻页寻找，回滚失败还是需要人工跟进的高危态。

**State completeness 扣分：**

- **-15 变更管理列表页无状态定义**（同 Requirement Coverage 所述，此处为状态完整性维度）：States 表只覆盖向导，列表自身的 Default/Loading/Empty/Error 缺失。
- **-6 向导状态转换触发条件未描述**。Step5（执行进度）→ Step6（验证窗口）是自动进入还是人工点击？"执行中 | 逐项状态实时刷新（2s 轮询）"到"验证中 | 窗口倒计时"之间无转换语义；Step6→Step7 同样未说明。
- **-4 配置页无 loading/error 态**。States 表只有 Empty/Default/渠道未确认/阈值越界，配置读取失败、保存接口异常的呈现未定义。

### 4. Implementability（开发者视角）— 156 / 250

| 子项 | 得分 | 说明 |
|------|------|------|
| Layout specificity | 61 / 80 | |
| Data binding explicit | 20 / 80 | 本设计最重扣分项 |
| Interaction unambiguity | 75 / 90 | |

**Layout specificity 扣分：**

- **-10 无响应式策略**。`内容最大宽 1200px` 是唯一的布局约束；台账表格 7 列、看板 5 列总览卡、向导清单表在 1200px 以下如何折行/横向滚动/隐藏列，全文未提。运维平台常见的 1366 笔记本与分屏场景无解。
- **-5 Drawer/Modal 尺寸未定义**。`Drawer z30`、`Modal z30` 只给了 z-index，宽度（引用资源抽屉、看板探测详情抽屉）、Modal 最大宽/是否可全屏均未定义。
- **-4 表格列宽与统计卡栅格未定义**。3 列统计卡、5 列总览卡、各表格列的宽度比例/最小宽空白，"行高 48px"是唯一的表格规格。

**Data binding explicit 扣分（孤儿元素规则 -30/个）：**

- **-30 台账"批量导入"按钮为孤儿元素**。布局 `[批量导入 Secondary]` 与空态 `"批量导入存量证书" Primary 按钮` 两次出现，Interactions 表与 Data Binding 表均无对应条目——它做什么、提交什么字段、数据源是什么，开发者只能猜。
- **-30 详情页"关联变更历史列表"为孤儿元素**。布局右列明确有 `关联变更历史列表`，但绑定表该区域仅写 `要素卡 | cert 全要素 | 证书详情接口`——变更历史是变更单数据（应源变更服务、含状态/时间字段），不属于证书要素，绑定落空。

（其余弱绑定：台账搜索框/筛选器/分页、看板筛选行与"最��巡检: 3h 前"、变更列表状态 Tab 均未在绑定表中有字段对应，随子项分数一并折损。）

**Interaction unambiguity 扣分：**

- **-8 向导步间导航与步骤条行为未定义**（同 UX 维度）：前进、跳步、取消、草稿保存（状态机有"草稿"态但无任何产生草稿的交互）全部空白。
- **-4 看板次行卡不可点？** 布局 `[次行: 差异告警数(N) · 探测豁免数(N)]` 与主行卡并列，交互表只有 `点击状态卡 | 表格按该分级过滤`——次行两卡是否联动过滤（差异→diff 行、豁免→exempt 行）未说明，行为不对称。
- **-3 "执行剩余批"入口位置不明**。交互有 `执行剩余批（首批验证通过后）| 剩余批清单确认 Modal`，但该入口出现在哪个页面（向导 Step6 内？列表行内？报告页？）未指明。

## Phase 3 — 盲点猎捕（[blindspot]，rubric 之外）

1. **[blindspot] 长任务无重入路径**：`执行中 | 逐项状态实时刷新（2s 轮询）` —— 变更执行+验证窗口是小时级长任务，用户关闭浏览器/断网后如何回到进度视图？列表"详情"是否复用向导 Step5/6 视图？设计中"报告详情页"本可承接（执行中单据点进去看实时进度），却因该页未定义而整条恢复链路断裂。这是运维工具最典型的故障场景。
2. **[blindspot] 只读角色派生路由拦截缺口**：`只读查看者：本页无任何操作入口；/certs 与 /certs/changes 路由前端拦截提示无权限` —— 只拦截了两条精确路由，`/certs/:id`（台账详情）、`/certs/changes/new`、`/certs/settings` 均为可达派生路由，只读用户可从看板分享链接/历史记录直达详情页。PRD 只列了两条，但设计作为实现契约应覆盖路由前缀族。
3. **[blindspot] 立即扫描的并发与结果时序**：`点击"立即扫描" | 触发引用扫描任务 | 按钮转 loading"扫描中"；完成 Toast + 刷新元数据` —— 扫描是分钟级异步任务，"完成 Toast"要求用户停留在页面；用户离开后扫描完成是否通知？再次点击是否防重（按钮 disabled？排队提示？）？对扫码期间发起的变更单（Step2 依赖"2h 前快照"）如何失效，未闭环。
4. **[blindspot] 空态引导互相矛盾**：台账空态 CTA 为 `"批量导入存量证书" Primary 按钮`，但"批量导入"本身无任何交互定义——新用户首次落地的第一按钮即是不存在的功能，bootstrap 场景（PRD 明确"空态引导指向批量导入/bootstrap"）在第一屏就断链。

**修复优先级建议（供 reviser）：**

1. 补齐"变更报告详情"组件定义（路由/布局/状态/绑定/行点击入口），并承接执行中单据的实时进度重入 —— 一并解决 nav gap 与 blindspot #1。
2. 为变更管理列表页补 Default/Loading/Empty/Error 状态，且向导补步间导航与 Step5→6→7 转换语义。
3. 定义"批量导入"完整交互与数据绑定（表单形态、校验呈现、进度反馈），消除最大孤儿元素。
4. 详情页"关联变更历史列表"补数据绑定（源变更服务）。
5. UF-2 正向引用补"按云/产品/集群筛选 + 搜索资源名"控件。
6. 增加无障碍基线：键盘/焦点管理、表单标签规范、非色觉状态通道、对比度声明。
7. #8b5cf6 纳入色板或改用既有 Accent；统一"详情/查看报告"命名；补 Tab 状态全集或说明取舍。
8. 补响应式策略与 Drawer/Modal 尺寸规格。
