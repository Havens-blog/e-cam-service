## Phase 1 — 推理审计摘要

五个 UI Function、三条一级导航、四个次级页面全部有组件与 Page Composition 对应；PRD 硬规则（盲区常驻、在途互斥、分批 ≤50%、回滚仅成功项、快照重校验回退 Step2、非色觉状态通道、批量导入中断语义、只读拦截、保护期行级标记、不可达渲染）均已落位。跨页一致性总体良好。

**只读角色 /certs/:id 开放的一致性核验**：设计声明只读者可经看板抽屉「查看证书详情」链接进入 /certs/:id 只读模式（仅查看要素与引用关系，隐藏「立即扫描」等操作入口）。PRD 导航规则仅声明 /certs 与 /certs/changes 对只读拦截，未显式禁止 /certs/:id；设计将其作为看板链接可达的次级页开放，与"只读者唯一菜单入口=到期看板"不冲突（不经菜单），内部自洽。但证书详情页 States 表无只读变体行（如"扫描超期"态在只读模式下按钮应隐藏），全局规则覆盖但组件级 States 表未反映——见 Design Integrity 扣分。

本轮新发现/持续问题集中于：响应式列优先级未随新增列同步更新、看板两筛选器无绑定、分批边界 total=1 失效、若干 iter-3 持续项。

## Phase 2 — 四视角评分

### 1. Requirement Coverage（PM 视角）— 242 / 250

| 子项 | 得分 |
|------|------|
| UI function coverage | 79 / 80 |
| Navigation Architecture coverage | 40 / 40 |
| State requirement coverage | 77 / 80 |
| Edge case handling | 46 / 50 |

**扣分明细：**

- **-2 看板空态缺引导**（状态覆盖）。PRD UF-3 空态为"空态引导"；设计看板空态仅 `Empty | "暂无证书，等待导入" | 只读者看到亦同`，无图标无 CTA，与全局空态模式"图标 + 一句话 + 主 CTA（与 PRD UF 空态引导一致）"直接冲突。台账/变更列表空态均有 Primary CTA，看板唯独缺席；工程师（可导入）在此无引导入口。
- **-1 证书详情页 States 表无只读变体**（状态覆盖）。全局规则声明只读模式隐藏「立即扫描」等操作入口，但详情页 States 表 `扫描超期 | 元数据行变 Warning + "立即扫描"按钮` 未反映只读模式下按钮隐藏的变体——只读者看到该态时按钮行为未在组件级定义。
- **-2 草稿并发编辑无冲突处理**（边缘条件）。`草稿/待确认单据行点击 | 进入向导恢复编辑`——两名工程师同时恢复同一草稿、或一人编辑另一人已确认执行的变更单，无乐观锁/冲突提示。
- **-1 普通工程师直达 /certs/settings 的拦截未声明**（边缘条件）。只读拦截清单覆盖六条路由（对只读角色）；配置页 Placement 写"仅运维主管/审计角色可见"（入口可见性），但普通工程师（非只读、非主管）直接输 URL 的前端拦截行为未定义。
- **-1 分批 floor(50%) 对 total=1 无效**（边缘条件）。`首批数量选择器上限 = floor(总量/2)`——总量=1 时上限=0，无法执行首批；total≤1 免分批的规则未声明。
- **-1 UI function 覆盖**：看板作为只读者唯一页面，空态对只读者是功能死胡同（无导入权限却显"等待导入"文案，无可达下一步），属 UF-3 覆盖的可用性缺口。

**正向认定**：五 UF 全覆盖；保护期行级标记（台账+变更列表）、不可达渲染、批量导入全生命周期（混合上传/单文件重试/中断留存/会话结果重入）、删除双分支、在途互斥、快照重校验回退 Step2、只读恢复视图（含部分完成回滚入口）、报告五卡、只读角色路由拦截与菜单不渲染，覆盖完整。

### 2. User Experience（终端用户视角）— 246 / 250

| 子项 | 得分 |
|------|------|
| Information hierarchy | 78 / 80 |
| Interaction intuitiveness | 79 / 80 |
| Accessibility | 89 / 90 |

**扣分明细：**

- **-2 覆盖率卡信息过载**（层级）。`覆盖率：登记 ≥90% 目标 / 可更换托管`——单卡塞入两口径＋目标值，现状值与目标值未视觉分离，用户难以快速判读是否达标。
- **-1 反向查询触发模式措辞不一**（直觉性）。布局 `Tab 反向：搜索框(域名/资源名，输入即过滤 + "查询"按钮)`（即时过滤口吻），交互表 `反向查询搜索 | 输入域名/资源名回车或点"查询"按钮`（提交查询口吻）——结果究竟是即时出现还是提交后出现，两处模式未统一，用户心智模型分裂。
- **-1 看板云 chips / 反向查询初始态无障碍标注**（无障碍）。看板行 `[阿里云][腾讯云]` 云 chips 为视觉徽章，未声明 aria-label；反向查询"未执行查询的初始态"无显式可访问文案/标签。无障碍规范覆盖键盘/焦点/标签/非色觉通道/对比度/动效/表格语义/landmark/skip link/高频通告，但这两处微观标注缺口犹存。

**正向认定**：landmark 与 skip link、长报告页 h2/h3 标题层级、高频轮询与倒计时读屏策略（跨小时档摘要通告、终态事件通告、reduced-motion 降级）、对比度规则（Text Secondary 限制使用场景+替代色 #a1a1a1）、焦点陷阱与归位、非色觉状态通道（图标+文字双通道）均已完整定义。

### 3. Design Integrity（设计师视角）— 245 / 250

| 子项 | 得分 |
|------|------|
| Design system adherence | 79 / 80 |
| Visual coherence | 87 / 90 |
| State completeness | 79 / 80 |

**扣分明细：**

- **-1 补充色相偏离 monochrome 体系**（adherence）。设计系统定义为"Black and white precision…Monochrome precision"，但 Color Palette 增补 `Warning #f5a623`、`Verifying #8b5cf6` 两个色相。虽限定为状态语义色非装饰，但 Vercel 黑白单 Accent 体系下引入两个新色相仍构成调色板漂移，设计师评审会标记。
- **-1 ◐ 图标语义复用**（一致性）。无障碍规范 `验证中=◐+「验证中」`，报告页卡2 `结果(成功✓/失败✗/限流重试中◐/跳过—)`——同一 ◐ 符号映射"验证中"与"限流重试中"两个状态，非色觉通道图标语义被稀释（文字标签虽区分，但视觉符号复用）。
- **-2 "已回滚/回滚失败"合并 Tab 粒度不一致**（一致性）。`"已回滚/回滚失败"为合并 Tab`——回滚失败是需人工跟进的高危终态，与正常已回滚合并后依赖行内徽章二次区分；而"部分完成"（同为非理想终态）单列 Tab，粒度不对称。
- **-1 证书详情页 States 表无只读变体**（状态完整性）。`扫描超期 | 元数据行变 Warning + "立即扫描"按钮`——只读模式下按钮应隐藏，但 States 表无只读变体行，状态完整性在组件级未覆盖只读分支。

**正向认定**：Vercel 设计系统规则（颜色/字体/组件/深度/布局）遵循度高；状态色映射统一且附非色觉通道；向导 7 步状态转换语义表完整（Step4→5/5→6/6→7 自动与人工转换、部分完成/已完成分支）；台账导入 Modal 处理中态已补齐。

### 4. Implementability（开发者视角）— 239 / 250

| 子项 | 得分 |
|------|------|
| Layout specificity | 75 / 80 |
| Data binding explicit | 76 / 80 |
| Interaction unambiguity | 88 / 90 |

**扣分明细：**

- **-3 表格列宽与卡片栅格 gap 无规格**（布局）。`行高 48px` 是唯一表格度量；各表格列最小宽/比例、3 列统计卡与 5+2 列总览卡的栅格 gap 未定，开发者需自行推测。
- **-1 配置输入控件形态二选一未决**（布局）。`滑块或数字输入`——"或"把决策留给开发，两控件的可访问性与错误提示行为不同。
- **-1 台账小屏列优先级未覆盖全部列**（布局）。响应式策略 `台账页保留 域名/SAN · 剩余 · 托管状态 · 操作，隐藏 签发者/引用数`——台账实际列含 `有效期`、`保护期`（新增），两列既不在保留集也不在隐藏集，小屏行为未定义。
- **-2 看板 状态分级/托管类型筛选器无绑定**（绑定）。看板绑定表仅 `云筛选器 | filterState.cloud`，`状态分级▾` 与 `托管类型▾` 两筛选器在绑定表无对应 filterState 条目（交互表仅泛称"筛选器变更 | 表格过滤 | 即时"）。
- **-1 看板行实体（证书 vs 子域名）未显式声明**（绑定）。绑定 `表格子域名行云 chips | referencedClouds[]（当前证书所引用资源的所属云去重集合）`暗示每行=证书，但列头为"子域名"，同子域名多证书时行数与去重规则未明示。
- **-1 批量导入"上次会话结果"留存来源未绑定**（绑定）。`重入页面后再开批量导入 Modal 展示上次会话结果列表`——会话结果从何接口取（batchImport 的 lastSession？）无字段绑定。
- **-1 Step2 阻断卡"立即扫描"完成后的回环未定义**（交互）。阻断卡提供 `「立即扫描」`，扫描完成后是否自动重跑 Step2 预检、还是人工再进 Step2，未说明。
- **-1 反向查询触发模式内部不一致**（交互）。布局 `输入即过滤 + "查询"按钮`，交互 `回车或点"查询"按钮 → 结果列表`——若结果仅提交后出现，"输入即过滤"无对象；若即时过滤，查询按钮冗余。开发者无法确定结果出现时机。

**正向认定**：只读恢复区条件矛盾已消除（部分完成的恢复区可见性与回滚入口宿主明确）；?certId= 预选语义完整（含不可更换提示）；台账搜索/筛选/分页绑定齐备且标注客户端/服务端；看板云筛选+最近巡检绑定齐备；五页面 Data Binding 表完整。

## Phase 3 — 盲点猎捕（[blindspot]，rubric 之外）

1. **[blindspot] 向导候选期不前置在途单/保护期状态**（iter-3 blindspot 2，仍未修复）：`下拉行 = 域名 + 指纹（mono 截断）+ 剩余天数`——在途单与保护期状态不进候选行，用户走完 Step2 预检、Step3 清单生成后才在互斥校验吃 `Error 提示"存在在途变更单 CHG-XXXX"`。错误后置到流程尾部，候选期前置标记成本远低于让用户白走两步。
2. **[blindspot] "提前完成"与剩余批的语义冲突**（iter-3 blindspot 3，仍未修复）：`窗口内全部达标也可提前点「提前完成」（二次确认）进入报告`——若存在剩余批（首批验证通过、剩余批未执行），"提前完成"是跳过剩余批还是仅跳过剩余等待？状态机行 `Step6 → Step7 | 验证窗口关闭（倒计时归零）且无剩余批` 只约束自动转换，人工提前完成的批次语义未定义。
3. **[blindspot] "发送测试"的测试对象未定义**（iter-3 blindspot 4，仍未修复）：`发送测试 | 触发测试告警 | 结果 Toast（成功/失败原因）`——测试的是输入框中的未保存草稿还是已持久化配置？用户修改 webhook 后直接点测试，可能误测旧配置并得到"成功"，形成假信心。
4. **[blindspot] 批量导入 zip 内非 PEM/嵌套 zip 的处理未定义**：`支持 zip 解包`——zip 内含非 PEM 文件、嵌套 zip、或超大 zip 的校验与逐项反馈未说明，属导入边界处理缺口。
