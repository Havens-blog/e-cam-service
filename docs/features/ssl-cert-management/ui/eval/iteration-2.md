## Phase 1 — 推理审计摘要

PRD 五个 UI Function 全覆盖，三条一级导航 + 四个次级页面全部有组件与 Page Composition 对应；PRD 的硬规则（盲区声明常驻、在途互斥、分批 ≤50%、回滚仅成功项、保护期、只读拦截、非色觉状态通道）均已落位。跨页一致性良好：状态徽章色映射全局统一，报告页与向导复用同一状态组件，抽屉/Modal 规格全局统一。剩余问题集中在三处：(a) 向导前半段（Step1~3）只有布局示意与前进校验，无逐步交互与绑定；(b) 若干元数据/统计字段无绑定或无口径；(c) 异步任务的并发/时序边界（扫描防重、批量导入中断）未闭环。

## Phase 2 — 四视角评分

### 1. Requirement Coverage（PM 视角）— 230 / 250

| 子项 | 得分 |
|------|------|
| UI function coverage | 74 / 80 |
| Navigation Architecture coverage | 38 / 40 |
| State requirement coverage | 76 / 80 |
| Edge case handling | 42 / 50 |

**扣分明细：**

- **-3 统计口径缺"仅指纹登记占比"**。PRD UF-1 统计概览三项："登记覆盖率、可更换托管覆盖率、仅指纹登记占比"；设计统计卡 `完整托管 (N) | 仅指纹登记 (N) | 覆盖率：登记 ≥90% 目标 / 可更换托管`，绑定表仅 `fingerprintOnlyCount`（绝对数），占比口径仍未呈现。
- **-2 配置页读取/保存异常态缺失**（计入 UI function 完整性）：配置页 States 仅 Empty/Default/渠道未确认/阈值越界，配置读取失败、保存接口异常无定义。
- **-2 /certs/settings 对普通工程师的直达拦截未声明**。只读拦截清单覆盖六条路由，但配置页权限仅写"仅运维主管/审计可见"，普通工程师直达 /certs/settings 的前端拦截行为未与只读拦截同等级明示。
- **-5 长文本溢出无规则**（边缘条件）。`SAN 列表(mono chips)`、台账列 `域名/SAN`、变更列表列 `旧证书→新证书` 面对多 SAN 证书与长域名无截断/折叠/tooltip 规则。
- **-3 立即扫描并发防重未定义**（边缘条件）。`点击"立即扫描" | 触发引用扫描任务 | 按钮转 loading"扫描中"`——多用户并发触发、扫描进行中重复点击的防重/排队语义缺失。
- **-5 向导 Step1~3 交互与数据来源未定义**（UF-4 前半程）。布局仅 `Step1 选择证书: 旧证书(指纹 mono) + 新证书选择器` 一行示意；旧证书从何选择（台账下拉？搜索？）、新证书是"从已导入完整托管证书中选"还是"现场上传"，PRD 语义（"选择旧证书 + 新证书"）与"选择器"措辞均未消除歧义；Step2 预检触发时机、Step3 清单生成 loading 态亦无交互条目。

**正向认定：** 批量导入完整流程（含混合上传、单文件重试、终止二次确认）、删除双分支拦截、在途互斥、未发现引用≠无引用、回滚失败转人工、报告五卡、只读恢复视图，均完整覆盖，予以认可。

### 2. User Experience（终端用户视角）— 236 / 250

| 子项 | 得分 |
|------|------|
| Information hierarchy | 76 / 80 |
| Interaction intuitiveness | 76 / 80 |
| Accessibility | 84 / 90 |

**扣分明细：**

- **-3 覆盖率卡信息过载**。`覆盖率：登记 ≥90% 目标 / 可更换托管` 单卡两口径加目标值，现状与目标未视觉分离。
- **-1 删除藏于 ⋯ 菜单**。`⋯ 菜单（删除、补传私钥[仅指纹登记行]）`——已可接受（⋯ 为常规模式），但删除的高危属性与补传私钥并列折叠，权重分配仍偏轻。

**Interaction intuitiveness：**

- **-3 看板次行卡行为不对称**。布局 `[次行: 差异告警数(N) · 探测豁免数(N)]` 与五行状态卡同区域呈现，交互表仅 `点击状态卡 | 表格按该分级过滤`——次行两数是否可点、是否联动过滤（差异→diff 行、豁免→exempt 行）未说明，用户会按卡片视觉等同性预期可点。
- **-1 反向查询空查询/无结果反馈未说明**。`搜索框(域名/资源名，输入即过滤 + "查询"按钮)` 已补按钮，但无匹配时的空态文案未定义（正向有"无匹配引用"，反向无对应）。

**Accessibility：**

- **-3 无跳转链接与地标角色**。无障碍规范覆盖键盘/焦点/标签/对比度/动效/表格语义，但未定义 skip-to-content、页面 landmark（nav/main）、页头 heading 层级，屏幕阅读器长页导航无规范。
- **-2 轮询状态更新的读屏通告范围过窄**。`分页、筛选器状态变化通过 aria-live="polite" 通告` 仅覆盖分页/筛选；执行进度逐项刷新（2s 轮询）、验证窗口倒计时这类高频变化是否通告、如何避免读屏刷屏未说明。
- **-1 倒计时无 reduced-motion 之外的认知降噪**。`验证窗口: 倒计时(如 22:31:05)` 秒级跳动对注意力的影响未提及更新粒度（秒/分级展示）取舍。

### 3. Design Integrity（设计师视角）— 231 / 250

| 子项 | 得分 |
|------|------|
| Design system adherence | 77 / 80 |
| Visual coherence | 84 / 90 |
| State completeness | 70 / 80 |

**扣分明细：**

- **-3 两个"补充"状态色游离于 Vercel 核心体系**。`Warning（补充） | #f5a623`、`Verifying（补充） | #8b5cf6`——已入色板且限定语义用途（好于 iter-1），但 Vercel 黑白体系 + 单 Accent 下引入两个新色相仍需在原型中验证共存效果，文档未给共存样例（如一行内同时出现 Warning 徽章 + Verifying 徽章 + Error 角标）。

**Visual coherence：**

- **-3 看板次行卡视觉形态未定义**。`[次行: 差异告警数(N) · 探测豁免数(N)]`——是卡片、行内文本还是徽章？与五行总览卡（明确为"卡"）的关系（嵌套？并排？）无描述，跨页看板视觉规格存在空洞。
- **-3 "已回滚/回滚失败"合并 Tab 的取舍代价**。`"已回滚/回滚失败"为合并 Tab，回滚失败行徽章为 Error + ⚠，Tab 内可再按徽章区分`——回滚失败是需人工跟进的高危终态，与已回滚（正常终态）合并后依赖行内徽章二次区分，与"部分完成"单列 Tab 的粒度不一致。

**State completeness：**

- **-4 配置页无 loading/error 态**（同 Requirement Coverage，此处为状态完整性维度）。
- **-4 向导 Step1~3 的组件级状态缺失**。向导状态表全部为执行期状态（阻断/执行中/验证中/…），Step1 选择器空态（无完整托管证书可选时）、Step2 预检 loading、Step3 清单生成中/生成失败无状态定义；"清单被阻断"仅覆盖校验失败分支。
- **-2 台账导入 Modal 无 loading 态**。导入提交（校验中）的上传/解析进度反馈未定义，仅定义了成功/失败两分支。

**Interaction unambiguity：**

- **-8 向导 Step1~3 无交互条目**。向导 Interactions 表 7 条中 5 条属 Step4~6/列表，Step1 的旧/新证书选择行为、Step2 的预检触发与"立即扫描"联动、Step3 的清单生成触发与刷新语义均无 Trigger→Action→Feedback 行；开发者只能从"向导步间导航"的前进校验反推。"下一步按钮仅在当前步校验通过后可用"给出了闸门，但没给每步的输入交互本体。

- **-3 看板次行卡交互缺失**（同 UX 维度）：行为不明即无法实现。

## Phase 3 — 盲点猎捕（[blindspot]，rubric 之外）

1. **[blindspot] 批量导入中断的服务端残留**：`不得中途关闭（关闭需二次确认"终止导入"）`——仅在 UI 层阻止关闭；浏览器崩溃/断电时已上传文件与部分入库记录的服务端清理、重开页面后的续传/重置语义未定义。上传类功能的恢复路径是典型故障场景，rubric 的状态维度覆盖不了"客户端中断 + 服务端半完成"组合态。
2. **[blindspot] 清单快照与确认时点的时效性校验**：`[清单绑定扫描: 2h 前快照]`——快照绑定在 Step3 生成时点；Step3 浏览清单到 Step4 确认之间若新扫描完成（引用集变化），确认时是否重校验快照新鲜度未定义。用户可能基于过期清单确认执行，这是数据一致性风险而非视觉/交互问题。
3. **[blindspot] 变更向导中"旧证书"候选集与保护期标记的联动**：PRD 要求"回滚保护期内旧证书行显示保护期标记"，设计在变更列表/报告页有 `protectDaysLeft`，但向导 Step1 选择旧证书时（`旧证书(指纹 mono)`），处于保护期内或已有在途单的旧证书在候选列表中如何标记/禁用（在途互斥仅在发起后报错 `存在在途变更单 CHG-XXXX`）未定义——错误后置到提交流程尾部，而候选期前置提示成本更低。
4. **[blindspot] 看板差异行的处置出口缺失**：`差异行 | 行内 Error 角标 + 最近探测时间 tooltip`——只读查看者（本页唯一可访问页的受众）发现差异后的上报/认领路径未定义；只读者无任何操作入口（`本页无任何操作入口`）意味着差异发现链路在看板侧终止，需依赖其他角色自行巡检同页。角色协作流是 PRD 未写、rubric 未覆盖的流程缺口。

**修复优先级建议（供 reviser，冲击 950）：**

1. 向导 Step1~3 补交互条目与数据绑定，并澄清"新证书选择器"来源（一次性解决两处最大失分）。
2. 看板次行卡定义视觉形态与交互（或显式声明纯展示）。
3. 配置页补 loading/error；向导前半段补组件级状态。
4. 统计卡补仅指纹占比；表格长文本截断规则。
5. 三个 blindspot 择要落文档：批量导入中断清理、Step4 快照重校验、只读者差异上报路径。
