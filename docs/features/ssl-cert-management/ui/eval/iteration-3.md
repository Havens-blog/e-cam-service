## Phase 1 — 推理审计摘要

五个 UI Function 与三条一级导航、四个次级页面全部有组件与 Page Composition 对应；PRD 硬规则（盲区常驻、在途互斥、分批 ≤50%、回滚仅成功项、快照重校验、只读拦截、非色觉状态通道、批量导入中断语义）均已落位。跨页一致性总体良好。本轮新发现三类问题：

1. **报告页"只读恢复区"自相矛盾**：布局限定"仅 执行中/验证中/部分完成 且窗口未关闭"，但状态转换表定义"部分完成"仅在窗口关闭时产生——空集条件；同时交互表又把"部分完成"的回滚入口放在恢复区内。
2. **PRD UF-4 流程 7"旧证书行保护期标记"未落位**：台账列、变更列表列均无该标记，仅报告页头有 `protectDaysLeft`。
3. **看板元数据/筛选绑定空洞**：筛选行三筛选器与"最近巡检"均无绑定，其中"云"筛选在表格无云列、绑定表无对应字段。

## Phase 2 — 四视角评分

### 1. Requirement Coverage（PM 视角）— 239 / 250

| 子项 | 得分 |
|------|------|
| UI function coverage | 74 / 80 |
| Navigation Architecture coverage | 40 / 40 |
| State requirement coverage | 78 / 80 |
| Edge case handling | 47 / 50 |

**扣分明细：**

- **-4 保护期标记未落到证书行**（UF 覆盖）。PRD UF-4 流程 7 明确"回滚保护期内旧证书行显示保护期标记"；设计台账列 `域名/SAN │ 签发者 │ 有效期 │ 剩余 │ 托管状态 │ 引用数 │ 操作`、变更列表列 `变更单号 │ 旧证书→新证书 │ 状态徽章 │ 进度 │ 发起人 │ 时间 │ 操作` 均无保护期标记；仅报告页头绑定 `protectDaysLeft`。行级标记这一 PRD 明示要求缺席。
- **-2 "不可达"探测状态无渲染规格**（UF 覆盖）。绑定表枚举含 unreachable（`probeStatus(consistent/diff/unreachable/exempt)`，与 PRD 四值一致），但视觉层仅定义 一致[Success]、豁免[Secondary]、差异（Error 角标）三种，"不可达"的徽章色/图标/文案无规格。
- **-2 看板空态缺引导**（状态覆盖）。PRD UF-3 空态为"空态引导"；设计看板空态仅 `"暂无证书，等待导入"`，无图标无 CTA，与全局空态模式"图标 + 一句话 + 主 CTA（与 PRD UF 空态引导一致）"直接冲突，全角色用户在此死路（台账/变更列表空态均有 Primary CTA）。
- **-2 草稿并发编辑无冲突处理**（边缘条件）。`草稿/待确认单据行点击 | 进入向导恢复编辑`——两名工程师同时恢复同一草稿、或一人编辑另一人已确认执行的变更单，无乐观锁/冲突提示。
- **-1 普通工程师直达 /certs/settings 的拦截未声明**（边缘条件）。只读拦截清单覆盖六条路由，配置页仅写"仅运维主管/审计可见"（入口可见性），普通工程师直接输 URL 的前端拦截行为未定义。

**正向认定**：批量导入全生命周期（混合上传/单文件重试/中断留存/会话结果重入）、删除双分支、在途互斥、快照重校验回退 Step2、只读恢���视图、报告五卡、只读角色拦截与菜单不渲染，覆盖完整。

### 2. User Experience（终端用户视角）— 239 / 250

| 子项 | 得分 |
|------|------|
| Information hierarchy | 78 / 80 |
| Interaction intuitiveness | 76 / 80 |
| Accessibility | 85 / 90 |

**扣分明细：**

- **-2 覆盖率卡信息过载**（层级）。`覆盖率：登记 ≥90% 目标 / 可更换托管`——单卡塞入两口径＋目标值，现状与目标未视觉分离。
- **-2 反向查询无结果反馈缺失**（直觉性）。`Tab 反向：搜索框(域名/资源名，输入即过滤 + "查询"按钮) → 结果: 该域名/资源引用的证书卡片列表`——无匹配时无空态文案（正向有"无匹配引用"，反向无对应），用户无法区分"无引用"与"查询未执行"。
- **-2 两套下钻模式不一致**（直觉性）。台账 `表格行点击 → 证书详情`（跳页），看板 `点击子域名行 | 右侧抽屉`（抽屉）——同为"查看这张证书"的心智，交互模型分裂；且看板抽屉内无任何去往证书详情/引用关系的入口，全角色用户从看板无法触达引用视图。
- **-2 无跳转链接与地标角色**（无障碍）。无障碍规范覆盖键盘/焦点/标签/非色觉通道/对比度/动效/表格语义，但 skip-to-content、landmark（nav/main）、heading 层级均未定义，长报告页（5 卡）读屏导航无规范。
- **-2 高频轮询的读屏通告策略缺失**（无障碍）。`分页、筛选器状态变化通过 aria-live="polite" 通告` 仅覆盖低频变化；执行进度 2s 轮询逐项刷新、验证窗口秒级倒计时是否通告、如何避免读屏刷屏无说明。
- **-1 倒计时秒级跳动无认知降噪**（无障碍）。`倒计时(如 22:31:05)` 秒级更新粒度对注意力的取舍（秒显 vs 分显）未提及。

| 子项 | 得分 |
|------|------|

**扣分明细：**

- **-1 补充状态色无共存样例**（体系 adherence）。`Warning（补充） | #f5a623`、`Verifying（补充） | #8b5cf6` 已限定语义用途，但 Vercel 黑白单 Accent 体系下双新增色相在同行共现（如 Warning 徽章 + Error 角标）的效果无样例说明。

- **-1 ◐ 图标语义复用**（一致性）。无障碍规范 `验证中=◐+「验证中」`，报告页卡2 又用 `限流重试中◐`——同一符号映射两个不同状态，非色觉通道的图标语义被稀释。
- **-2 台账导入 Modal 提交中无 loading 反馈**（状态完整性）。`导入提交（校验失败）/ 导入提交（成功）` 仅定义终态两分支，上传/解析/校验进行中的按钮态与进度反馈未定义（批量导入有进度条，单张导入反而没有）。

### 4. Implementability（开发者视角）— 229 / 250

| 子项 | 得分 |
|------|------|
| Layout specificity | 76 / 80 |
| Data binding explicit | 71 / 80 |
| Interaction unambiguity | 82 / 90 |

**扣分明细：**

- **-3 表格列宽与卡片栅格无规格**（布局）。`行高 48px` 是唯一表格度量；各表格列最小宽/比例、3 列统计卡与 5+2 列总览卡的栅格 gap 未定。
- **-1 配置输入控件形态二选一未决**（布局）。`滑块或数字输入`——"或"把决策留给开发，两控件的可访问性与错误提示行为不同。
- **-3 看板筛选行整行无绑定**（绑定）。`[筛选行: 状态分级▾ 云▾ 托管类型▾ | 最近巡检: 3h 前]` 在看板绑定表中无任何条目；其中"云"筛选尤其成问题：表格列无云字段（`domain / daysLeft / level / hostingType / probeStatus`），按云过滤的对象与效果无数据支撑。
- **-2 "最近巡检"未绑定**（绑定）。布局展示 `最近巡检: 3h 前`，绑定表无 lastInspectionAt/lastInspectedAt 对应字段。
- **-3 台账搜索/筛选/分页无绑定且无标注**（绑定）。`搜索框 | 筛选: 托管状态▾ 剩余天数▾` 与分页控件在绑定表无条目；详情页正向筛选已明确写"客户端状态（前端过滤 refs[]）"，台账未沿用同一标注方式，客户端/服务端过滤规格不对称。
- **-1 批量导入"上次会话结果"留存来源未绑定**（绑定）。`重入页面后再开批量导入 Modal 展示上次会话结果列表`——会话结果从何接口取（batchImport 的 lastSession？）无字段。
- **-3 只读恢复区条件自相矛盾**（交互无歧义）。布局 `[只读恢复区(仅 执行中/验证中/部分完成 且窗口未关闭)]`，但状态转换表定义 `窗口关闭时存在未达标/失败项 → 部分完成`——"部分完成 且窗口未关闭"是空集；同时交互表 `回滚成功项（恢复区内，仅 执行中[出现失败后]/验证中/部分完成 可用）` 又把部分完成的回滚入口放进恢复区。开发者无法确定部分完成单据的恢复区与回滚入口位置（交互表与布局冲突）。
- **-2 ?certId= 预选语义未定义**（交互）。`路由跳转 /certs/changes/new?certId=`——参数是否预选 Step1 旧证书、预选后能否更换，无说明。
- **-1 Step2 阻断卡"立即扫描"完成后的回环未定义**（交互）。阻断卡提供 `「立即扫描」`，扫描完成后是否自动重跑预检、还是人工再进 Step2，未说明。
- **-1 反向查询触发措辞内部不一致**（交互）。布局写 `输入即过滤 + "查询"按钮`（客户端过滤口吻），交互表写 `输入域名/资源名回车或点"查询"按钮`（服务端查询口吻），两处模式描述不一致。

## Phase 3 — 盲点猎捕（[blindspot]，rubric 之外）

1. **[blindspot] 看板抽屉是全角色的引用关系死胡同**：`点击子域名行 | 右侧抽屉：证书要素 + 最近探测详情（探测时间/线上指纹/差异说明）`——抽屉仅含要素+探测，无"查看证书详情/引用关系"链接。只读者被路由拦截尚可理解，但工程师从看板发现问题时必须手动去台账搜索同名证书才能看引用。跨页流程上下文在此断裂，rubric 的单页交互维度覆盖不了这种"页间可达性"缺口。
2. **[blindspot] 向导候选期不前置在途单/保护期状态**（iter-2 blindspot 3，仍未修复）：`下拉行 = 域名 + 指纹（mono 截断）+ 剩余天数`——在途单与保护期状态不进候选行，用户走完 Step2 预检、Step3 清单生成后才在互斥校验吃 `Error 提示"存在在途变更单 CHG-XXXX"`。错误后置到流程尾部，候选期前置标记成本远低于让用户白走两步。
3. **[blindspot] "提前完成"与剩余批的语义冲突**：`窗口内全部达标也可提前点「提前完成」（二次确认）进入报告`——若存在剩余批（首批验证通过、剩余批未执行），"提前完成"是跳过剩余批还是仅跳过剩余等待？状态机行 `Step6 → Step7 | 验证窗口关闭（倒计时归零）且无剩余批` 只约束了自动转换，人工提前完成的批次语义未定义。
4. **[blindspot] "发送测试"的测试对象未定义**：`发送测试 | 触发测试告警 | 结果 Toast（成功/失败原因）`——测试的是输入框中的未保存草稿还是已持久化配置？用户修改 webhook 后直接点测试，可能误测旧配置并得到"成功"，形成假信心。属工作流语义缺口，非视觉/绑定问题。

**修复优先级建议（供 reviser，冲 950+）：**

1. 消除恢复区"部分完成且窗口未关闭"空集条件，明确部分完成的回滚入口宿主（交互/布局冲突是本轮最大单点失分）。
2. 台账与变更列表补保护期标记；看板补"不可达"渲染。
3. 看板筛选行/最近巡检、台账搜索/筛选/分页补绑定与过滤标注。
4. 看板抽屉补"查看证书详情"入口；反向查询补空态；单张导入补提交中反馈。
5. 四个 blindspot 择要落文档：候选期前置在途/保护期标记、「提前完成」×剩余批语义、「发送测试」对象。
