## Phase 3 — 盲区猎捕（[blindspot]，均在 rubric 维度之外）

1. **[blindspot] 状态机「关闭」终态不可达** — prd-spec.md L100「`…已回滚 / 回滚失败(转人工) → 关闭`」声明了到「关闭」的转移，但三份文档没有任何一处定义触发「关闭」的动作或条件：草稿被放弃会关闭吗？部分完成后长期不执行剩余批（P3 场景）会自动关闭吗？回滚失败转人工后人工处理完由谁关闭？状态迁移测试无法覆盖终态，UF-4 状态表也无「关闭」行的展示定义。
2. **[blindspot] 分批与回滚的交互语义未定义** — spec L53「首批执行且验证通过后方可继续执行剩余批」与 L54「回滚入口在执行中（出现失败项后）、验证中、部分完成状态均可用；范围限本次变更涉及资源」组合后：若首批成功项在续批前被回滚，剩余批是否仍可执行？回滚范围是「本次变更全部成功项」还是「当前批成功项」？回滚后变更单进入「已回滚」还是可继续续批？两套规则交叉的用例无法构造预期结果。
3. **[blindspot] 同一指纹证书重复导入无定义** — 指纹是引用聚合、清单匹配、映射表的唯一主键，但「导入新购证书」与「存量批量导入」均未定义：导入一张指纹已存在台账的证书时，是去重合并（如补齐私钥）、覆盖更新、还是报错？bootstrap 批量导入与新购导入通道重叠时行为一致吗？该边界直接影响台账唯一性与登记覆盖率的分子。
4. **[blindspot] 只读查看者默认页跳转链路未定义** — UF-3 Placement 称「到期看板（全角色，只读者默认页）」，但只读角色登录 e-cam-web 后从平台首页/根路由到 /certs/dashboard 的跳转逻辑（其一级菜单仅此一项）未在任何导航规则中声明；若平台默认路由指向其他功能域，只读用户的落点与无权限提示链路不可测。此为导航级细节，rubric 维度未覆盖。

### 修订指令（给 reviser）

1. **C4（必改，-30）**：将 prd-ui-functions.md UF-1 交互流第 3 步错误清单中的「SAN 不含」移出拦截类，改为独立提示类展示（或改写为「SAN 结构无法解析」并确认与 spec 四类校验一致）。
2. **P1**：将「资产同步独立盘点」显式列入 In Scope 交付物或标注为与 K8s 凭证同级的前置依赖，并在 Data Flow 表补对应行（或声明降级行为）。
3. **P2**：定义状态机「关闭」的进入条件（草稿废弃/人工关闭/转人工处理完毕）及 UF-4 对应状态行。
4. **P3 + blindspot 2**：补分批规则的两条分支：首批部分失败后剩余批的处理；回滚与续批的交互（回滚范围、回滚后能否续批、变更单终态）。
5. **blindspot 3**：定义重复指纹导入行为（去重/更新/报错）及其对覆盖率分子的影响。
6. 小项：为「批量执行成功率 ≥ 95%」补统计窗口；补运维工程师「处理告警」故事或 AC；为审计「不可修改」定义可执行验证手段（如再次写入被拒）；设定证书/私钥上传大小上限；补单云扫描部分失败时覆盖率与「未发现引用」的展示口径；定义回滚失败转人工后的状态出口。
