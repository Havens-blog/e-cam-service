# User Stories: SSL 证书统一托管与更换

## Story 1: 导入新购证书

**As a** 运维工程师
**I want to** 上传新购证书文件（PEM + 私钥）并自动完成完整性校验与要素解析入库
**So that** 新证书进入统一台账，无需手工登记，且不合格文件在入口即被拦截

**Acceptance Criteria:**
- Given 一套证书与私钥匹配、证书链齐全、未过期的证书文件
- When 运维工程师在证书台账页上传并提交
- Then 系统校验通过，解析出 SAN/签发者/有效期/指纹并加密存储私钥，台账出现该证书
- Given 导入表单中可选填写的"预期域名"
- When 提交导入
- Then 系统仅对"解析出的 SAN 是否覆盖预期域名"作提示性比对展示，比对不一致不拦截入库（域名覆盖的强制校验发生在变更清单预检处，见 Story 3）
- Given 一套证书与私钥不匹配（或证书链缺失/已过期/SAN 结构无法解析）的文件
- When 运维工程师上传提交
- Then 系统 100% 拦截并给出具体错误原因，不入库
- Given 任意查询证书详情的请求
- When 前端页面或 API 返回数据
- Then 任何情况下均不包含明文私钥

## Story 2: 查看证书引用关系

**As a** 运维工程师
**I want to** 查看任一托管证书被哪些资源引用（多云 CDN/DCDN/WAF/LB、K8s 网关 CRD）
**So that** 换证前清楚知道影响面，日常能回答"这张证书动过哪里"

**Acceptance Criteria:**
- Given 一张已被引用的托管证书且最近扫描在新鲜度阈值内
- When 运维工程师打开其引用关系视图
- Then 按云/产品/集群分组展示全部引用资源，并显示最近扫描时间与覆盖率元数据
- Given 任意引用关系视图
- When 页面渲染
- Then 页面显式标注覆盖边界："本视图不含 VM Nginx 配置级引用"
- Given 一张已入台账但扫描未发现引用的证书
- When 查看引用关系
- Then 标记为"未发现引用"（区别于"无引用"），并提示扫描时间
- Given 同一域名存在多张未过期证书
- When 查看引用关系
- Then 按证书指纹区分展示各证书各自被引用的资源，互不混淆

## Story 3: 一键批量更换

**As a** 运维工程师
**I want to** 导入新证书后按指纹匹配旧证书全部引用点，确认变更清单后一键批量执行，并跟踪逐项进度与失败回滚
**So that** 一次换证从十几处手工高危操作变为一轮平台内可控变更

**Acceptance Criteria:**
- Given 新证书已导入、旧证书引用扫描在新鲜度阈值内
- When 运维工程师对旧证书发起更换
- Then 系统生成按指纹聚合的变更清单（含每项资源、计划动作、原证书 ID、覆盖边界声明），并完成 SAN ⊇ 目标域名预检（此处为域名覆盖的强制校验点）
- Given 变更清单中包含华为云/AWS/Azure 引用点或被 GitOps/控制器管理的 K8s 资源
- When 清单生成
- Then 该类目标单列为"不可执行项/不可自动变更"分区，显式标注原因（首期无部署器 / 受外部管理系统管理）与出路（二期处理或手工更换 / 走其管理链路如 GitOps 仓库），不参与自动执行，不计入批量执行成功率分母
- Given 最近一次扫描已超出新鲜度阈值
- When 发起更换生成清单
- Then 系统阻断清单生成并提示先完成新一轮扫描
- Given 同一旧证书已存在一张活跃（待确认/执行中/验证中）变更单
- When 运维工程师再次对该旧证书发起更换
- Then 系统阻断并指向在途变更单
- Given 一份已确认的变更清单
- When 批量执行中有部分资源失败
- Then 失败项保留旧证书引用、成功项正常完成，进度逐项可见（含"限流重试中"状态），整体不中断
- Given 批量执行后存在失败项、或验证窗口内发现成功项线上异常，且云侧旧证书仍存在未过期
- When 运维工程师对**成功项**执行回滚（执行中（出现失败项后）、验证中、部分完成状态均提供回滚入口）
- Then 回滚将成功项引用恢复为旧证书 ID；执行失败项的引用从未被改动、无需回滚，仅在变更报告中标记；若旧证书已删除/已过期则提示转人工决策并记录
- Given 变更完成进入验证窗口（2~24 小时）
- When TLS 探测发现线上证书与变更清单预期终态不一致（含部分成功分裂状态）
- Then 以"变更关联告警"呈现而非常规差异告警；窗口关闭或全部达标后恢复正常告警；窗口关闭仍未达标的项转为常规差异告警并记入报告"未达标清单"
- Given 一份总量较大的已确认变更清单
- When 运维工程师选择分批执行（单批不超过总量一半）
- Then 首批执行且验证通过后，同一变更单内可继续执行剩余批，剩余批同样需人工确认后执行，全部批次完成后生成整体变更报告
- Given 批量执行全部成功且验证窗口内全部达标
- When 窗口关闭
- Then 变更单进入已完成状态，恢复正常告警规则，旧证书进入回滚保护期（7~14 天），变更报告记录全部成功结果与验证结论
- Given 执行中两段式第二段（绑定资源）失败触发孤儿证书补偿清理
- When 运维工程师查看变更报告
- Then 报告含孤儿证书补偿清理结果（逐项清理成功/失败），清理失败项触发告警

## Story 4: 存量证书初始导入

**As a** 运维工程师
**I want to** 批量导入存量证书并回收私钥，无法回收者登记为仅指纹登记
**So that** 平台上线即有完整台账，引用关系与到期监控立即生效

**Acceptance Criteria:**
- Given 一批存量证书文件（含或不含私钥）
- When 运维工程师批量导入
- Then 含私钥者成为完整托管证书；不含私钥者登记为"仅指纹登记"（可监控可展示引用，不可自动更换）
- Given 存量导入完成
- When 查看台账统计
- Then 展示登记覆盖率与可更换托管覆盖率两个指标，"仅指纹登记"占比单独可见
- Given 私钥后续被定向回收
- When 运维工程师补传私钥并通过匹配校验
- Then 该证书升级为完整托管

## Story 5: 审计与告警配置

**As a** 运维主管/审计
**I want to** 审阅每次变更的报告与全量操作日志，并配置告警规则、全局接收人与探测豁免清单
**So that** 全网证书变更有据可查，告警触达可控

**Acceptance Criteria:**
- Given 至少一次已完成的变更
- When 运维主管打开变更报告
- Then 报告含变更清单、逐项结果、回滚状态、验证结果、孤儿证书补偿清理结果；对应审计记录含操作人/时间/操作对象/结果且仅追加、不可修改——可通过审计接口按变更单号查询并与报告逐条比对一致来验证
- Given 全局告警配置（webhook + 邮件接收人）
- When 到期/差异/变更关联/回滚失败事件触发
- Then 按已配置渠道触达全局接收人
- Given 若干内网不可达子域名
- When 运维主管将其加入探测豁免清单
- Then 这些端点不再参与常规 TLS 差异告警，豁免清单变更留审计记录
