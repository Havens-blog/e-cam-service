# 需求卡：探测目标分类治理（内网域 / 僵尸记录 / 协议记录）

**状态**：需求卡待评审（未实现）。
**来源**：2026-11-13 生产探测数据全量盘点（3029 域）+ 150 样本 DNS 实测。

---

## 一、证据

`GET /api/v1/certs/probes?limit=5000` 全量 3029 域，状态分布：consistent 1567 / unreachable 1212 / diff 189 / wildcard_skipped 61。

对 `unreachable` 1212 个往下拆：

| 子类 | 数量 | 判定方法 |
|---|---|---|
| 重复后缀畸形（已由 #634 修复）| 252 | 正则匹配 `x.<suffix>.<suffix>` |
| **非畸形 unreachable** | **960** | — |

对 960 个按 `i%6` 等距抽样 150 个做 DNS A 记录解析：

| 分类 | 样本数 | 占比 | 外推全量 | 说明 |
|---|---|---|---|---|
| **解析到内网 IP** | 118 | 79% | **≈755** | `10.x` / `192.168.x` / `172.16-31.x`；含 `dev-*`、`*-inner-*` 等明显内网命名 |
| **NXDOMAIN（无此域）** | 23 | 15% | **≈147** | 平台 DNS 记录已过期/已删（僵尸记录）|
| 解析到公网 IP 但 TLS 失败 | 9 | 6% | ≈58 | 真问题，值得逐条排查（如 `ahlslive.sz-jlc.com`、`box.forface3d.net`）|
| 其它错误 | 0 | 0% | 0 | — |

另查到 **32 个含下划线标签的域名**（`_<hash>.domain` 的 ACME DNS-01 记录、`strong2._domainkey.domain` 的 DKIM 记录），全部 unreachable。现有代码只跳过 **rr 前缀**为下划线的记录，**标签中段的 `_domainkey` 漏过**。

## 二、问题陈述

1. **内网域（≈755，占全部探测域 25%）** 会被每轮拨测——公网探测端永远拨不通，只能落 `unreachable`。后果：① 可达率指标被稀释（真实可达率被低估约 25 个百分点）；② 白耗拨测并发（16 并发 × 数千目标，内网域占 1/4 的拨号预算）。
2. **僵尸记录（≈147）** 是平台侧数据陈旧（DNS 记录在云上已删，平台未回收），会长期占用清单。
3. **协议记录漏网（32）** 属分类口径不全：下划线标签本质是协议用途（ACME/DKIM/SPF），不可能是 TLS 端点。

## 三、目标 / 非目标

**目标**
- 拨测前分类：内网域、协议记录（任一标签以 `_` 开头）**不拨测**，以独立状态呈现（`internal` / `protocol_skipped`）；
- 可达率、差异率等指标按「可拨测域」为分母计算，语义不再被内网域稀释；
- NXDOMAIN 域名打上「疑似僵尸」标记（连续 N 轮 NXDOMAIN），供运维批量清理。

**非目标**
- 不自动删除 DNS 记录（清理需人工确认）；
- 不改变 `diff` / `consistent` 判定口径；
- 不改既有 `wildcard_skipped` 语义（通配符 SAN 跳过仍保留）。

## 四、方案

### 4.1 分类时机
在 `probe_service.go` 生成探测目标后、拨测前做一次分类（`classifyTarget(hostname) → skipReason`，纯函数、可表驱动测试）：
- `hasUnderscoreLabel(hostname)` → `protocol_skipped`
- 解析到内网 IP（RFC1918 + 100.64/10 + 169.254/16 + 127/8）→ `internal`
  - 实现方式：拨测前的 `Dial` 已拿到连接目标 IP；可在 Dial 结果里带出 `RemoteIP`，命中私网段即判 `internal`（不新增 DNS 查询开销）。

### 4.2 状态常量
`ProbeStatus` 增加两个取值：`internal`、`protocol_skipped`（DB validator 的枚举同步扩两项）。

### 4.3 指标口径
`dashboard_service` 的 rate 计算分母改为「可拨测域数 = 总数 − internal − protocol_skipped − wildcard_skipped」，并在响应里单列各跳过类计数（前端已按类别展示，新增两项即可）。

## 五、验收标准

1. 表驱动单测：`classifyTarget` 覆盖 RFC1918 各段、`100.64/10`、`169.254`、`127.0.0.1`、IPv6 私网、下划线各位置（首/中/尾标签）、正常公网域；
2. 指标测试：分母口径切换后 `reachableRate` 提升可量化（示例：现状 51.7% → 剔除内网后约 69%）；
3. 真实数据验证：下一轮探测后 `status=unreachable` 数量应从 1212 降至 ≈58（真不可达）+ 0（畸形已修）；
4. 浏览器：看板「探测覆盖」区块出现新分类计数，且百分比之和为 100%。

## 六、风险与回滚

| 风险 | 缓解 |
|---|---|
| 私网判定误伤（如运营商 NAT 后公网域解析到 100.64/10）| 100.64/10 列为可配置（默认判 internal，可关） |
| 指标口径变更影响历史对比 | 保留旧口径字段（`totalDomains`），新增字段并存一个版本 |
| 状态枚举扩项影响前端展示 | 前端按未知状态兜底展示为「其它」，先加后端再看板补文案 |

回滚：新增状态为附加字段，回滚仅需恢复枚举与分母逻辑（revert 单 PR）。
